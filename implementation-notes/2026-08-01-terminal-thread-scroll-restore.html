Summary

Goal
Open completed single-prompt threads at the user prompt instead of the bottom spacer.
Source

Algorithm

  1. Collect rendered .message-item.user rows and the latest user target.
  2. Allow restore when an assistant row exists, multiple user rows exist, or isTerminalStatus(effectiveStatus(currentThread)) and exactly one user row exists.
  3. Scroll to target.top + window.scrollY - offset after the queued bottom-follow callbacks.

UI layout

  1. Thread stage: use grid-template-rows: auto minmax(0, 1fr) and align-content: start so the sticky header row cannot stretch into blank space.
  2. Thread workspace: use min-height: 100%, a column flex container, and margin-top: auto on #prompt-form so the composer stays low on short threads.

Decisions

IDChoice - Rationale
D-001Treat completed, ready, and failed single-prompt threads as restorable. They no longer need live-tail startup behavior.
D-002Keep active single-prompt threads excluded. Brand-new runs still need the live-tail behavior from followLatest().
D-003Make the thread stage rows explicit. CSS grid stretch was placing row-two content after a viewport-sized row-one gap.
D-004Push the composer with a full-height flex column and auto margin. The prompt should start near the header while the composer remains bottom-biased on short threads.
