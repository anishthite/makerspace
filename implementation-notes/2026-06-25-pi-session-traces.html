Pi session traces

main · worktree /Users/anishthite/workspace/makerspace · 2026-06-25 · status shipped · blast medium

Summary

Goal
Persist each Pi SDK run as a JSONL session trace instead of using only in-memory session managers.
Source
SessionManager.create(cwd, sessionDir) from the Pi SDK.
Surface
Host dispatch, local folder runs, and bridge-backed Daytona runs.
Schema
Add optional local trace directory config; existing data/sessions.json shape stays compatible.
Storage
Local traces default to data/pi-sessions/ or ~/.makerspace/pi-sessions/; remote bridge traces stay in /srv/micro-cloud/pi-sessions/.
Open Qs
0.

Plan

  1. Add piSessionTraceDir config with PI_SESSION_TRACE_DIR override.
  2. Use SessionManager.create for local and host Pi SDK sessions.
  3. Use SessionManager.create(workspaceDir, sessionDir) in the generated bridge script.
  4. Emit one system log line with the generated session file path.
  5. Ignore default trace files in git and document the env var.

Decisions

IDChoice · Rationale
D-001Use Pi's native JSONL session manager. It records the real conversation tree without inventing a second trace format.
D-002Keep remote traces in the sandbox control directory. Pulling remote JSONL back to the control server adds network copies and auth surface.
D-003Log the trace file path as a system event. It exposes the location without a new API.

Tradeoffs

IDPicked over Rejected · Reason
T-001Pi JSONL over custom event JSONL. The SDK already persists messages, tool calls, model changes, and tree IDs.
T-002Trace path log over stored metadata. The user asked for disk traces, not UI browsing.
