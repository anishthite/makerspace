Project workspace mode

main · worktree /Users/anishthite/workspace/makerspace · 2026-07-01 · status shipped · blast high

Summary

Goal
Reuse one durable remote workspace per ownerUserId + repoUrl and run each thread in its own worktree.
Flag
MAKERSPACE_WORKSPACE_MODE=1; hosted mode requires GitHub auth for ownership.
State
Workspace rows stay in makerspace_sessions; lookup index uses makerspace_kv.
Remote layout
/srv/workspace/main plus /srv/workspace/tasks/<thread>.
Bridge
POST /runs accepts a validated cwd under /srv/workspace.
Verification
PATH=/opt/homebrew/bin:$PATH npm test passes.
Open Qs
0.

API contract

POST /runs
{
  id: string,
  name: string,
  prompt: string,
  cwd?: string
}

Algorithm

  1. Normalize repoUrl and compute workspaceKey = sha256(ownerUserId + repoUrl).
  2. Read workspace:index:<ownerUserId>:<repoHash>; verify the session row still exists and belongs to the user.
  3. Create a workspace row and Daytona sandbox when the index is missing or stale.
  4. Bootstrap the workspace idempotently: clone/fetch repo into /srv/workspace/main without deleting the whole workspace.
  5. Create /srv/workspace/tasks/<thread> from main with git worktree add -f.
  6. Start the thread bridge run with cwd set to that task directory.

Decisions

IDChoice · Rationale
D-001Use existing session rows for workspace records. Avoid a new table while the session store already supports D1/file fallback.
D-002Require ownerUserId when hosted workspace mode is enabled. Cross-user repo sharing would leak code, installs, and auth.
D-003Create one workspace bridge per repo and one run at a time per workspace. Parallel remote Pi sessions can come after the durable workspace path works.
D-004Keep clean sandbox mode as the fallback when MAKERSPACE_WORKSPACE_MODE is off. Repro/risky tasks still need disposable sandboxes.

Tradeoffs

IDPicked over Rejected · Reason
T-001KV index plus JSON workspace row over normalized tables. Existing D1 client is a tiny REST wrapper and JSON rows keep the diff small.
T-002Git worktrees over full reclones. Reuse Git objects and project caches while isolating task edits.

Assumptions

  • A-001 · Daytona stopped sandboxes retain disk until autodelete; if wrong, workspace mode must switch to setup-recipe/image restore.
  • A-002 · One active run per workspace is acceptable for the first implementation; if wrong, add a per-workspace queue or multiple bridge services.

Reversibility

R-001 · high. Unset MAKERSPACE_WORKSPACE_MODE to return to current per-thread sandbox behavior while leaving old workspace rows inert.

Definition of done

  • Same signed-in user and repo reuses one workspace row/sandbox.
  • Different users with the same repo get separate workspaces.
  • Threads run in separate remote worktree paths under /srv/workspace/tasks.
  • Remote bridge rejects cwd outside /srv/workspace.
  • Focused tests pass.
