Decisions

IDChoice · Rationale
D-001Extract by existing function clusters. Moving stable seams lowers behavior risk.
D-002Keep Node http.createServer. A router dependency adds migration risk for no user-visible gain.
D-003Use explicit dependency objects between modules. This avoids singleton drift and keeps tests able to stub config/provider later.
D-004Defer broad logic rewrites. The first pass is movement plus tiny dedupe only where repetition blocks clean extraction.
D-005Keep route-only imports in routes.js. The dispatcher owns settings/report/profile/recents endpoints without creating extra service files.
D-006Add resetRunState in run-state.js. One helper removes repeated reset literals without changing launch flows.
D-007Apply safe review cleanups only. Duplicate same-origin guards, repeated viewer/trusted lookups, dead auth timestamps, renamed logout helper, and bridge-session literals are removed.
D-008Add generateShortText in thread-title.js. Title and final-summary generation use the same SDK/auth/completion path.

Tradeoffs

IDPicked over Rejected · Reason
T-001Six server modules over one module per route. Route-level files would multiply imports and hide shared lifecycle state.
T-002Service functions over classes. There is one runtime instance, so classes would be ceremony.
T-003Focused regression tests over new snapshot tests. Existing route tests already exercise the public contract.
T-004Small bridge helpers over one generic launcher. Failure persistence and claimed-run start are shared while each launch flow keeps its status text.
T-005Keep /api/performance alias. Possible external callers beat deleting one harmless route condition.
T-006One private short-text helper over two copied exported flows. The public title/summary functions keep their signatures.

Assumptions

  • A-001 · Existing tests cover the critical public behavior; manual smoke is only needed if full tests expose a gap.
  • A-002 · Current dirty workspace changes are intentional user work; this task avoids reverting unrelated files.

Reversibility

R-001 · medium. Revert the extraction commit to restore the single-file server without data migration.

  • No new dependency, framework, or speculative abstraction.
