Multi-user Git control

Summary

Goal
Give each signed-in user's Daytona sandbox authenticated git and gh access for private repos.
Auth
Prefer GitHub App installation tokens; fall back to the user's existing GitHub OAuth token.
Surface
/api/auth/github/app/install, /api/auth/github/app/callback, Settings GitHub panel.
Storage
Store installation ids by owner login in user KV; never persist clone headers in sessions.
Blast
High: sandbox agents can push to repos covered by user OAuth/App permissions.

API contract

POST /api/auth/github/app/install
{ "returnTo": "https://app/settings.html" }
→ { "installUrl": "https://github.com/apps/<slug>/installations/new?state=..." }

GET /api/auth/github/app/callback?installation_id=99&state=...
→ 302 /settings.html?githubApp=installed

Algorithm

  1. Settings starts GitHub App install after normal GitHub sign-in.
  2. Callback verifies state and stores installation_id under the installed owner login.
  3. Repo launch parses github.com/<owner>/<repo> and mints an installation token for that owner.
  4. Setup script normalizes GitHub SSH URLs to HTTPS, seeds git/gh credentials, and clones with http.extraHeader.
  5. Persisted sessions replace repoAuthHeader with an empty string before disk write.

Decisions

IDChoice · Rationale
D-001Prefer GitHub App tokens over OAuth tokens. They are short-lived and owner-scoped.
D-002Keep OAuth as fallback. Existing users and repo picker already depend on it.
D-003Authenticate any parsed github.com repo URL. Pasted private URLs fail before repo-picker metadata exists.

Tradeoffs

IDPicked over Rejected · Reason
T-001Owner-login installation map over per-repo grants. GitHub App installation ownership is enough to mint tokens for selected repos.

Assumptions

  • A-001 · Operators configure the GitHub App setup URL as /api/auth/github/app/callback; if wrong: install completes on GitHub but Workbench cannot store the installation id.
  • A-002 · The GitHub App has Contents read/write and optional Pull requests/Workflows permissions; if wrong: clone may work but push/PR/workflow edits fail.

Reversibility

R-001 · high. Remove app env, route handlers, Settings button, and token preference to return to OAuth-only sandbox git auth.
