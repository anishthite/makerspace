Summary

Goal
Run each local Spanner main agent in a fresh Git worktree instead of the selected checkout.
Source
repoPath local folders and ensureLocalGitRepo() GitHub clones supply the source checkout.
Surface
POST /api/threads, /, /workspace.html, sidebar prompt launch.

~/spanner/<repo>/<thread-slug> from main; override base with SPANNER_WORKTREE_BASE_DIR, exact root with SPANNER_WORKTREE_DIR, and Git base with branch.

API contract

Request

POST /api/threads
{
  repoPath?: string,
  repoUrl?: string,
  branch?: string,      // base branch/ref; default "main" for local worktrees
  prompt: string,
  name?: string
}

Response — Thread

{
  repoPath: string,          // worktree path when localWorktree=true
  sourceRepoPath?: string,   // original selected checkout or cached GitHub clone
  worktreePath?: string,
  worktreeBaseRef?: string,
  worktreeBranch?: string,
  localWorktree?: boolean
}

Keep branch; do not add baseRef until users need branch and base to mean different things.

Algorithm

  1. Resolve the source checkout: repoPath via provider.resolveRepoPath(), or repoUrl via ensureLocalGitRepo().
  2. Find the Git root with git -C <source> rev-parse --show-toplevel; fail with a clear message if the folder is not a Git repo.
  3. Set baseName = branch || "main"; fetch origin baseName when an origin remote exists.
  4. Resolve baseRef in order: origin/<baseName>, <baseName>, HEAD.
  5. Set worktreeRoot = SPANNER_WORKTREE_DIR || (SPANNER_WORKTREE_BASE_DIR || ~/spanner)/<repo-leaf>.
  6. Set worktreeBranch = spanner/<thread-slug>-<hash> and worktreePath = <worktreeRoot>/<thread-slug>.
  7. Run git worktree prune, then git worktree add -B "$worktreeBranch" "$worktreePath" "$baseRef"; reuse an existing valid worktree for the same thread.
  8. Start local Pi with repoPath = worktreePath and persist the source/worktree fields for UI labels and PR delivery.

UI layout

  1. Project launch: show a compact Base input beside the selected repo; default text is main or the GitHub default branch.
  2. Sidebar launch: reuse the selected project branch; no extra modal step.
  3. Thread header: show worktreePath in the path subtitle when localWorktree is true.

Decisions

IDChoice · Rationale
D-001Use Git worktrees for local launches. One source clone can back many isolated agents.
D-002Reuse branch as the base selector. Existing API and UI already carry it.
D-003Create a real spanner/<thread> branch per worktree. Local users can commit, diff, and push without first leaving detached HEAD.
D-004Fetch requested remote bases with refs/heads/<base>:refs/remotes/origin/<base>. Shallow single-branch cached clones otherwise leave the requested base only in FETCH_HEAD.
D-005Fall back from missing requested base branches to the repository default HEAD. Existing cached clones should still launch when main is absent.
D-006Use ~/spanner/<repo>/<workspace> for the default worktree layout. Supersedes T-001 and the temporary <repo>/.spanner choice after user clarified the desired path.

Tradeoffs

IDPicked over Rejected · Reason
T-001<repo>/spanner over ~/.spanner/worktrees. Superseded by D-006.
T-002No auto-delete over cleanup-on-thread-delete. Removing a worktree can delete unpushed user work.
T-003One helper in src/local-git.js over a new worktree service. The git surface is small.

Definition of done

  • Launching two local agents for the same repo creates two distinct ~/spanner/<repo>/<thread> worktrees.
  • The original checkout does not receive agent file edits.
  • The base selector defaults to main and accepts a user-provided branch.
  • git status in the original checkout stays clean because the worktree directory is outside the primary checkout.
  • node --test test/local-git.test.js test/session.test.js test/thread-lifecycle.test.js passes.
