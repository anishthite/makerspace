Paseo/bb link opening

main · worktree /Users/anishthite/workspace/makerspace · 2026-08-12 · status shipped · blast medium

Summary

Goal
Make assistant message links classify once and open through explicit browser/Electron paths.
Source
User asked to replace Spanner's current behavior with the Paseo/bb pattern.
Surface
/thread.html message links, Electron external opener, thread file-serving routes.
Schema
No persisted data change; one read-only thread file route.
Open Qs
0; use safe in-app preview as the default for local files.

Algorithm

  1. Classify links as external, app, artifact, or workspace-file.
  2. Open external through an http(s) allowlist only; Electron revalidates.
  3. Open app in the same tab; open artifact through existing artifact routes.
  4. Open workspace-file through a thread-scoped read-only route with path normalization and byte caps.

Decisions

IDChoice · Rationale
D-001Use one frontend classifier. Paseo and bb both separate target detection from the final opener.
D-002Make local files in-app first. Browser users cannot launch native editors and Electron users still need the same safe preview path.
D-003Drop editor custom schemes from the external opener. Native editor opening belongs behind a file-target bridge, not arbitrary message URLs.

Tradeoffs

IDPicked over Rejected · Reason
T-001Small file content route over a full editor-target registry. The user asked for link behavior, not an editor-picker system.
