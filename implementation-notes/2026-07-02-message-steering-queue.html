Summary

Goal
Send messages while an agent is running: steer interrupts the current run and followUp waits until the run drains.
Source
User asks for steering, queueing, and a small composer label.
Surface
POST /api/threads/:name/messages, generated bridge server, local Pi runner, and /thread.html composer.
Schema
No new stored shape; accepted user messages append to existing threadMessages[].
Open Qs
0.

API contract

POST /api/threads/:name/messages
{
  "prompt": "Stop and do X",
  "delivery": "steer" | "followUp" | "auto",
  "submittedAtMs": 1783000000000,
  "images": []
}

Algorithm

  1. If the thread is idle, keep the existing follow-up run path.
  2. If the thread is actively running, forward delivery to Pi's native steer() or followUp().
  3. Append the accepted user message to threadMessages[] with the current run id.
  4. Forward Pi queue_update events to the browser so the label can show pending counts.
