HTML img workspace paths

main · worktree /Users/anishthite/workspace/makerspace · 2026-07-03 · status shipped · blast low

Summary

Goal
Let assistant HTML <img src="output/foo.png"> render workspace images without duplicate artifact cards.
Source
Existing thread artifact file route and safe image path normalizer.
Surface
/thread.html assistant HTML preview iframe.
Schema
No data change.
Mobile
Use existing iframe/image max-width behavior.
Open Qs
0; only safe relative image paths are rewritten.

Algorithm

  1. Extract assistant HTML as before.
  2. Rewrite only <img> src attributes whose value normalizes as a relative image artifact path.
  3. Point rewritten sources at /api/threads/:name/artifacts/file?path=...&browserSession=....
  4. Skip automatic image artifact cards for HTML previews so the inline <img> is the only image rendering.

Decisions

IDChoice · Rationale
D-001Rewrite in the preview HTML builder. It keeps the iframe sandbox and CSP unchanged.
D-002Reuse the artifact file route. It already enforces thread access, relative paths, extensions, size, and content type.
D-003Skip image artifact cards for rendered HTML. The <img> tag should own image placement.

Tradeoffs

IDPicked over Rejected · Reason
T-001Targeted <img> attribute rewrite over general HTML proxying. Less code and smaller attack surface.
T-002Relative paths only over absolute filesystem paths. Browser-rendered assistant output must not expose host paths.
