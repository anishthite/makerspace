API contract

POST /api/threads/:name/suspend
→ 200 { provider, thread }

POST /api/threads/:name/resume
→ 202 { provider, thread }

POST /api/threads/:name/delete
→ 202 { provider, thread, snapshot }

Rules:
- suspend only when the thread is not actively running
- suspend preserves daytonaSandboxId/daytonaSandboxName
- resume starts the same sandbox, refreshes preview URL/token, syncs auth, returns ready/launching
- delete snapshots first; if snapshot fails, do not delete

Algorithm

  1. Fix Daytona list collection: for await (const sandbox of client.list(query)).
  2. Make setup idempotent: if /srv/workspace/.git exists, fetch instead of rm -rf.
  3. Default new remote control path to /home/daytona/.spanner/control; keep old path readable for existing sessions.
  4. Add provider lifecycle calls: suspendSession(session) sets long/disabled autodelete then sandbox.stop(); resumeSession(session) calls ensureStarted(), setup, preview, auth sync.
  5. Add destructive delete path: reject active runs, scrub sandbox secrets, call Daytona snapshot, persist snapshot ref, then delete sandbox.
  6. Add thread service routes that reject active runs, update status to suspended/ready/snapshotting, and retain sandbox refs.
  7. Teach UI to show suspended state with a resume action; do not call it pause.
  8. Add one provider unit test for list collection and one setup-script test proving existing git checkout is not removed.

Decisions

IDChoice · Rationale
D-001Implement suspend as Daytona sandbox stop, not Pi process pause. Live LLM process checkpointing is not available.
D-002Disable or extend autodelete before manual suspend. A user-initiated suspend must not delete work after the old 120-minute default.
D-003Use /home/daytona/.spanner/control for machinery. Repo cleanup and Git diffs should not touch Spanner control files.
D-004Keep Git/PR as the durable code save path. Daytona disk is runtime persistence, not backup.
D-005Snapshot before app-owned destructive delete. If snapshot fails, keep the sandbox and surface the failure.
D-006Sanitize before snapshot. Daytona snapshots capture the filesystem, so bridge env, git tokens, and Pi auth must be removed and later resynced.

Tradeoffs

IDPicked over Rejected · Reason
T-001Stop/start sandbox over snapshot on every suspend. Snapshots add latency/cost and belong on delete/reset/migration paths.
T-002Idempotent setup over migration script first. New resumes stop losing work without touching every old sandbox.
T-003Explicit suspended status over reusing ready. The UI needs to distinguish stopped compute from idle running bridge.

Assumptions

  • A-002 · Manual suspend is only allowed for non-active runs; active run stop remains the existing bridge /runs/:id/stop.
  • A-003 · Workspace mode remains the preferred durable repo path for signed-in user+repo projects.

Reversibility

Definition of done

  • Daytona list/reuse works with the installed async-iterator SDK.
  • Waking a normal git sandbox never deletes existing uncommitted files in /srv/workspace.
  • Suspending an idle thread stops compute and preserves its sandbox refs.
  • Resuming starts the same sandbox, refreshes bridge URL/token, syncs auth, preserves a marker file in /srv/workspace, and accepts a new prompt.
  • Manual delete persists a sanitized snapshot ref before sandbox deletion; failed snapshots block deletion.
  • Remote Spanner machinery no longer lives under the repo/worktree path.
