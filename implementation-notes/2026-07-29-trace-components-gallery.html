UI layout

  1. Element catalog: render #trace-elements as one specimen per component family with no full-thread shell.
  2. Messages: render user, assistant, colored turn status, raw text mode, and copy affordance.
  3. Timeline: render run summary open/collapsed, thinking, status, metric, log, system, workflow, summary, note, and legacy-log entries.
  4. Tools: keep grouped literal details.tool-card examples for file, shell, research, coordination, experiment, and goal tools.
  5. Missing states: render approval, parallel tool group, streaming output, cancelled run, redaction, retry, artifact failure, and subagent handoff specimens.
  6. Rail and artifacts: render workflow graph, diff box, notes rail, diagram, HTML, interactive, and OpenUI artifact shells.
  7. Trace reference library: render dark grouped trace header, read/write/bash/web/error rows, code output, final summary, user attachment bubble, changed-file strip, and a missing-states panel.

Decisions

IDChoice · Rationale
D-001Use literal runtime class structures. The renderer still owns behavior and this route is for visual review.
D-002Keep fake content inline. The board should load without thread API state.
D-003Disable content-visibility only for the gallery. Browser full-page screenshots otherwise skip offscreen specimens.
D-004Add #trace-library and ?view=trace-library as a separate reference-library view so the existing board remains available.
D-005List missing trace states on-page. The screenshots do not show approval prompts, parallel child tool groups, streaming partial output, cancellation, redactions, retries, artifact failures, or subagent handoff summaries.
D-006Add #trace-elements for isolated specimens. The full mock and old board make relationships visible, but individual component review needs one-element-at-a-time scanning.
D-007Mock missing states with existing visual vocabulary. Use tool-card, workflow-view-node, artifact cards, and status pills where those semantics already exist.
