API contract

GET /api/threads/:name/artifacts/state?path=artifact.html&key=landing-rubric
→ { path, key, data, updatedAt, found }

POST /api/threads/:name/artifacts/state?path=artifact.html
{ "key": "landing-rubric", "data": [...] }
→ { path, key, data, updatedAt, saved: true }

Algorithm

  1. HTML artifact calls parent.postMessage({ type: 'spanner:artifact-state:save', key, data }).
  2. Thread page finds the iframe whose contentWindow matches event.source.
  3. Thread page ignores artifact-supplied paths and uses frame.dataset.artifactPath.
  4. Thread page sends same-session GET/POST requests to the state endpoint.
  5. Thread page replies to the iframe with loaded, saved, or error.

Decisions

IDChoice · Rationale
D-001Use postMessage instead of allow-same-origin. The artifact stays origin-isolated while still getting a save path.
D-002Persist state in the thread session. Artifact drafts belong to the conversation that rendered them.
D-003Keep the payload generic JSON with a 256KB cap. Rubrics/forms fit; larger documents should become files.

Tradeoffs

IDPicked over Rejected · Reason
T-001One state endpoint over a new artifact database. Existing session storage already handles file and D1 modes.
T-002Parent-verifies-frame over iframe credentials. The sandboxed iframe has an opaque origin by design.
