Summary

Goal
Make reopened desktop threads show prior tool/thinking/workflow trace cards even after the server lost activeRuns.
Source
Pi stores append-only JSONL session files with a header line plus typed entries; Spanner currently stores trace events only in memory.
Surface
recordRunEvent(), GET /api/sessions/:name/output, thread bootstrap output, and frontend/src/runtime/thread.js.
Schema
Add traceStoreDir config. Local storage writes <traceStoreDir>/<encoded-session-name>.jsonl; D1 stores a capped JSON value keyed by trace:<session-name>.

Decisions

IDChoice - Rationale
D-001Use a sidecar trace store over writing into Pi session files. The UI events are Spanner projections, not Pi's canonical conversation tree.
D-002Keep live run IDs reset per run and mark replayed events as historical. This preserves the desktop stale-EventSource fix from 2026-07-16.
D-003Append asynchronously and warn on failure. A slow disk or D1 write should not stall the visible run stream.
D-004Cap replay events at the same 2000 event window as activeRuns.events. Assistant transcript text remains in existing message/output storage.

Tradeoffs

IDPicked over Rejected - Reason
T-001JSONL sidecar over stuffing sessions.json. High-frequency trace events would make the session index large and contention-prone.
T-002D1 KV whole-document writes over a new trace table. It matches existing state-store primitives and is enough for a capped window.

Assumptions

  • A-001 - Session names are stable IDs for trace history. If rename semantics are added later, move or alias the sidecar file.
  • A-002 - Historical events should restore trace cards, not assistant transcript chunks. The transcript is already persisted as messages.
