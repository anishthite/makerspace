UI layout

  1. Button, Badge, Tooltip replace leaf controls and status pills first.
  2. Select, Slider, Switch, InputGroup replace settings and run controls next.
  3. InputMessage replaces workspace/thread composers after DOM selector parity is pinned.
  4. ThinkingSteps and ThinkingIndicator replace live status, trace, and running-agent summaries.
  5. ScrollArea adds edge fades to timelines, traces, repo lists, and performance tables.
  6. Tabs/TabsSubtle, Dialog, and Dropdown handle settings grouping, focused overlays, and menus.
  7. AskUserQuestions renders structured agent questions inside thread messages.

Decisions

IDChoiceRationale
D-001Use shadcn as the local ownership model.Generated source fits this app better than a hidden component package.
D-002Install Fluid components one at a time.InputMessage and motion utilities pull real dependencies, so unused components are waste.
D-003Keep public/styles.css during migration.The current MPA already depends on this CSS for parity.
D-004Omit Tailwind preflight.Global reset drift would break existing handcrafted pages.
D-005Prefer Radix-flavored components where focus, portals, or keyboard behavior matter.shadcn defaults and accessibility behavior are already Radix-aligned.
D-006Ship CSS-only Fluid wrappers before Tailwind.Superseded by D-007.
D-007Install the full current shadcn UI set and keep runtime wrappers native where selectors depend on real form elements.The user asked for all shadcn components, but existing runtime code still needs native select, range, and checkbox nodes.
D-008Vendor actual Fluid components for visible controls.Superseded by D-012; actual Fluid controls were removed once the shadcn preset became the desired starting point.
D-009Remove the docs-style showcase from the app.The product should use real controls, not display a demo grid.
D-010Apply shadcn preset bIkfnxT.The user wants npx shadcn@latest apply --preset ... to be the component starting point.
D-011Put the final app design system in frontend/src/styles/design-system.css.Future shadcn applies can rewrite generated files while one local file still controls app-wide radius, spacing, inputs, cards, and tokens.
D-012Switch wrappers back to generated shadcn primitives.Button, badge, slider, switch, and tabs now start from the preset components while retaining runtime-safe native proxies.
D-013Reset to shadcn preset defaults.Remove mouse glow, diagonal background, Fluid CSS classes, and the extra app design-system override file; keep only a small token bridge for legacy CSS variables.

Tradeoffs

IDPicked over RejectedReason
T-001Incremental islands over full design-system rewrite.Thread streaming and desktop packaging are too easy to regress.
T-002Tailwind utilities without preflight over full Tailwind preflight.Generated shadcn classes work while old handcrafted page CSS keeps its reset.
T-003Provider wrapper over per-component token props.Surface, shape, icon, and reduced-motion policy stay centralized.
T-004Local Fluid-inspired wrappers over applying the Fluid registry directly.The registry dry-run writes UI files under backend src/components in this repo layout.
