Allowed origin list

push-prep/20260708-171222 · worktree /Users/anishthite/workspace/makerspace · 2026-07-09 · status shipped · blast medium

Summary

Goal
Accept several hosted frontend origins from env while preserving credentialed CORS allowlisting.
Source
User asked DigitalOcean env origins to accept a list, not one URL.
Surface
WORKBENCH_ALLOWED_ORIGIN(S), legacy origin aliases, OPTIONS /api/*, auth mutation origin checks, OAuth return URLs, SSE headers.
Schema
Env value becomes comma/newline-separated; no stored data change.
Open Qs
0.

Algorithm

  1. Parse configured origins with the existing comma-list convention.
  2. Reflect Origin only when it exactly matches the allowlist.
  3. Keep the first configured origin as the no-request fallback for old call sites.
  4. Use the same allowlist for auth redirects and mutation origin checks.

Decisions

IDChoice · Rationale
D-001Use comma/newline-separated env values. DigitalOcean env fields stay one variable and Node config already parses comma lists.
D-002Add plural aliases but keep WORKBENCH_ALLOWED_ORIGIN. Existing deployments should only edit the value, not rename envs.
D-003Reflect only exact allowlist matches. Credentialed CORS cannot send a wildcard or a comma-separated origin value.

Tradeoffs

IDPicked over Rejected · Reason
T-001Request-aware headers over multiple static headers. Browsers accept only one Access-Control-Allow-Origin.
