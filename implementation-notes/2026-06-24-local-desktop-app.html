Summary

Goal
Reuse public/ in a local app that can run Pi against a user-selected local folder.
Source
INFRA_PROVIDER=local, local filesystem paths, Pi SDK auth on the machine.
Surface
POST /api/threads accepts repoPath; npm run desktop:dev starts the Electron shell.
Schema
Session rows gain repoPath, localMode, and provider="local".
Mobile
Untouched.
Open Qs
0.

API contract

POST /api/threads
{
  repoPath: "/Users/me/project",
  prompt: "Fix the tests",
  name?: "thread-name"
}
{
  provider: { kind: "local" },
  thread: { name, repoPath, localMode: true, runStatus }
}

Algorithm

  1. Start backend with INFRA_PROVIDER=local; default data files to ~/.makerspace.
  2. Validate repoPath with realpath and stat.isDirectory().
  3. Create a thread row, then run Pi SDK with cwd=repoPath.
  4. Publish existing chunk, tool, metric, and status SSE events.
  5. Electron launches the local backend and exposes only chooseFolder() to the renderer.

Decisions

IDChoice · Rationale
D-001Run Pi directly with the SDK for local mode. Avoid starting a local bridge process just to call the same SDK.
D-002Keep public/ shared. Vercel and desktop load the same UI files.
D-003Ship an Electron dev shell first. It matches the existing Node backend and avoids a Tauri sidecar rewrite.
