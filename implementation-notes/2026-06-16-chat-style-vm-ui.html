API contract

{
  "prompt": "Build the first version of the app."
}

GET /api/sessions/:name/output?offset=0
200
{
  "session": { "name": string, "status": string, "sshDest": string, "httpsUrl": string, "commands": { ... } },
  "chunk": "new text since offset",

  "runStatus": "ready" | "running" | "completed" | "failed" | "unknown",
  "warning": string?
}

Algorithm

  1. Accept a prompt; normalize it into a private blank-repo session with autoRunAgent=true.
  2. Launch the VM through the existing provider path; persist the session as before.
  3. Poll remote pi.log from a byte offset; return only the unread suffix plus remote STATUS.
  4. Render prompt + streamed output in a chat transcript; stop polling on completed or failed.

UI layout

  1. Hero: say the app feels like chat while still running a fresh remote VM.
  2. Chat panel: show prompt history, streaming assistant output, and one textarea composer.
  3. Advanced panels: keep image settings and raw VM session table below the chat surface.

Decisions

IDChoice · Rationale
D-001Launch a fresh blank-repo VM per prompt. Smallest path from input box to remote run without adding stateful multi-turn session routing.
D-002Poll incremental log output over plain HTTP. Keeps the browser surface simple and still feels live at 1s cadence.
D-003Return from launch requests before VM creation finishes. Prevent the browser from sitting on a long ssh exe.dev new call and timing out.

Tradeoffs

IDPicked over Rejected · Reason
T-001polling output endpoint over WebSocket or SSE. Smaller server diff; enough for first-pass chat feel.
T-002one prompt = one VM over reusing one long-lived VM. Avoid command multiplexing and remote session bookkeeping.

Assumptions

  • A-001 · A fresh blank repo is acceptable for the first prompt-only UI. If wrong: add repo selection as an advanced option.
  • A-002 · One-second polling is close enough to “real time” for this surface. If wrong: swap the transport, keep the UI.

Reversibility

R-001 · medium. Restore the old launch form and remove the polling endpoints; persisted session data stays compatible.

Definition of done

  • The homepage leads with one prompt box instead of the old launch form.
  • Submitting a prompt creates a VM-backed run without asking for manual session metadata.
  • The browser appends remote output as it arrives and stops on completion or failure.
  • Launch requests return immediately instead of waiting for full VM provisioning.
  • Tests pass.
