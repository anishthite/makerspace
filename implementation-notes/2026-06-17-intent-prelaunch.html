intent prelaunch

nogit · worktree /Users/anishthite/workspace/makerspace · 2026-06-17 · status shipped · blast medium

Summary

Goal
Make normal browser submits use a fresh client-owned prepared bridge, not a global warm pool.
Trigger
public/app.js calls POST /api/bridge-intents on page load, focus, typing, and after completion.
Submit path
The browser keeps submit disabled until its intent bridge is ready; POST /api/chat claims that same clientId bridge.
Schema
data/sessions.json stores intentBridge, bridgeOwnerId, and preparedAt for prep sessions.
Verification
npm test passes; isolated live run with WARM_BRIDGE_POOL_SIZE=0 measured 118 ms and 95 ms.
Evidence
implementation-notes/artifacts/2026-06-17-cold-intent-measure.txt used empty stored sessions and fresh intent bridges.
Open Qs
0.

API contract

Request

POST /api/bridge-intents
{
  "clientId": "browser-or-script-id"
}

Response

{
  "provider": object,
  "clientId": string,
  "session": Session
}

Algorithm

  1. Normalize clientId; create one if the caller omits it.
  2. Return an existing unclaimed ready or launching intentBridge for that clientId.
  3. Otherwise create one bridge VM with empty prompt and bridgeOwnerId=clientId.
  4. On POST /api/chat, claim a ready owned bridge before unowned idle bridges.
  5. If the owned bridge is still launching, save the prompt there; the launch worker starts pi after auth and bridge readiness.

Decisions

IDChoice · Rationale
D-001Use browser intent instead of WARM_BRIDGE_POOL_SIZE. Capacity follows active clients.
D-002Store bridgeOwnerId on prep sessions. A client claims the bridge it caused.
D-003Attach submits to still-launching intent bridges. Early submit avoids duplicate cold launches.
D-004Prefer a client's owned launching bridge before unrelated idle bridges. The cold-path proof must not pass by stealing hidden warmed state.
D-005Disable normal browser submit until the owned bridge is ready. Supersedes A-001 for the UI path.
D-006Measure with an isolated SESSION_DATA_PATH and --require-empty-sessions. Stored warm bridges cannot satisfy the verifier.

Deviations

IDDeviation · Reason
X-001Supersedes A-001 for normal browser submits. The UI now waits for ready prep instead of assuming typing time is long enough.

Tradeoffs

IDPicked over Rejected · Reason
T-001Intent prelaunch over always-on pool. Idle capacity is bounded by active browser sessions.
T-002Client-generated ID over auth user ID. The app explicitly has no auth surface.
T-003Submit-ready gate over accepting immediate clicks. The measured submitted-query path stays honest and subsecond.

Assumptions

  • A-001 · Superseded by D-005. Immediate direct API submit before prep remains cold-start bound.
  • A-002 · Direct API callers that omit clientId still choose fresh launch or idle reuse. If wrong: add an API-level ready gate.

Reversibility

R-001 · medium. Remove /api/bridge-intents, clientId wiring, submit gating, and intent fields to return to idle-reuse-only behavior.

Definition of done

  • POST /api/bridge-intents starts at most one unclaimed prep bridge per clientId.
  • POST /api/chat uses the ready owned prep bridge before unrelated idle bridges.
  • The browser starts prep before submit, polls readiness, and gates submit until ready.
