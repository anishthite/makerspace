Summary

Goal
Let the user edit a Dockerfile in the UI and make new exe.dev sessions launch from the resulting image.
Source
exe.dev new --image plus the existing local image/Dockerfile.
Surface
GET /api/settings, POST /api/settings, POST /api/sessions, public/index.html.
Schema
data/settings.json for image metadata; image/Dockerfile for Dockerfile text.
Build
Optional local docker build and docker push before launch.
Open Qs
0.

API contract

GET /api/settings
{
  imageRef: string,
  registryAuth: string,
  autoBuildImage: boolean,
  dockerfile: string
}

POST /api/settings
{
  imageRef: string,
  registryAuth: string,
  autoBuildImage: boolean,
  dockerfile: string
}

Algorithm

  1. Read the saved image settings from data/settings.json and Dockerfile text from image/Dockerfile.
  2. Save settings edits back to those same files.
  3. When launching a session, if imageRef is set and autoBuildImage is true, generate a temporary Docker build context, run docker build, then docker push.
  4. Pass --image imageRef to ssh exe.dev new; add --registry-auth when configured.

UI layout

  1. Settings panel: image ref, registry auth, auto-build toggle, Dockerfile textarea, save button.
  2. Launch form: mention that launches use the saved image when present.

Decisions

IDChoice · Rationale
D-001Keep the Dockerfile in image/Dockerfile. The repo already treats that as the image source of truth.
D-002Save image metadata in data/settings.json. Keep mutable local config out of source-controlled files.
D-003Build and push locally before launch when enabled. exe.dev consumes image refs, not raw Dockerfiles.

Tradeoffs

IDPicked over Rejected · Reason
T-001docker build + docker push over pretending a Dockerfile can be sent straight to exe.dev. Matches exe.dev's real image model.
T-002plain-text local registry auth over a separate secret store. Smallest thing that works for a local control panel.

Assumptions

  • A-001 · Docker is installed on the local machine when autoBuildImage is enabled. If wrong: launch should fail loudly.
  • A-002 · The user has already authenticated locally for docker push. If wrong: the push step will fail and show the registry error.

Reversibility

R-001 · medium. Delete the settings API and UI panel; old setup-script launches still work.

Definition of done

  • The page has a settings panel for Dockerfile-backed image launches.
  • Saving settings updates image/Dockerfile and data/settings.json.
  • Session launch uses the configured image, with optional pre-launch build/push.
  • Tests pass.
