Codex device authentication

codex-device-code-auth · makerspace-codex-device-code-auth · 2026-10-10 · ready-for-review · medium

Summary

GoalAuthenticate a local Spanner user through Codex device-code login instead of requiring an API key for login.
Surfacespanner login, local credential file, README, and focused HTTP tests.
SchemaStore OAuth access/refresh tokens, expiry, and ChatGPT account ID in a user-only JSON file.
ScopeAuthentication only; the existing OpenAI-compatible inference client remains until a Codex runtime is selected.
Open Qs0; user selected authentication only.

Algorithm

  1. Request a device code from auth.openai.com.
  2. Print the trusted verification URL and one-time code.
  3. Poll until approval or the 15-minute expiry.
  4. Exchange the authorization code with its PKCE verifier and persist the token response with 0600 permissions.

Decisions

D-001Use Codex’s device-code protocol. It works without a callback listener.
D-002Write credentials under ~/.spanner/auth.json. Tokens stay outside the repository and use user-only permissions.
D-003Leave inference unchanged. ChatGPT Codex OAuth does not authenticate the existing /chat/completions client.

Tradeoffs

T-001Direct standard-library HTTP over adding an OAuth dependency. The protocol needs four small requests and is covered by a fake server.

Reversibility

R-001 · Medium: delete internal/codexauth and the CLI route; remove ~/.spanner/auth.json to revoke local persistence.

Definition of done

  • spanner login displays the Codex device code and persists a successful token exchange.
  • Credentials never appear in terminal output or the repository.
  • go test ./... passes with no real OpenAI account.
