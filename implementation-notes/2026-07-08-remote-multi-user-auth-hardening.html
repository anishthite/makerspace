Remote multi-user auth hardening

Summary

Goal
Keep hosted GitHub status tied to the auth cookie and make hosted Claude Code sign-in avoid fixed localhost port conflicts.
Source
User reports another GitHub login appeared in Settings and Claude Code shows listen EADDRINUSE 127.0.0.1:53692.
Surface
src/server/auth.js, src/server/routes.js, src/server/threads.js, focused auth tests.
Schema
No new persisted fields; reuse encrypted claude-code-auth and GitHub OAuth rows.
Open Qs
0.

Algorithm

  1. Hosted GitHub status ignores legacy x-workbench-session token state unless a signed auth cookie resolves to a user.
  2. GitHub OAuth callback requires the short-lived signed nonce cookie from the browser that started login.
  3. Hosted auth mutation POSTs reject cross-site origin/fetch metadata unless using the control token.
  4. Hosted Claude Code login builds Anthropic PKCE auth URL and waits for a pasted localhost redirect URL without binding 127.0.0.1:53692.
  5. Code submission validates OAuth state, exchanges tokens, and stores {type:'oauth',access,refresh,expires} in the existing per-user secret.

Decisions

IDChoice · Rationale
D-001Manual-only hosted Claude OAuth. The remote backend localhost callback cannot receive a user's browser redirect and the fixed Pi SDK port blocks concurrent users.
D-002Keep local Claude login on Pi SDK. Desktop/local can use the existing callback server and avoids duplicating more provider behavior.
D-003Disable hosted GitHub browser-session fallback. Signed cookies are the user identity; legacy browser session ids are not enough for multi-user auth.
D-004Deny implicit GitHub account switches. A signed-in user must sign out before replacing the Workbench auth cookie with another GitHub account.
D-005Use a short-lived signed GitHub OAuth nonce cookie. OAuth state alone can be replayed into another browser.
D-006Check origin on hosted auth mutation POSTs. SameSite is config-dependent, so route-level rejection is cheaper than trusting cookie policy.

Tradeoffs

IDPicked over Rejected · Reason
T-001Small embedded Anthropic token exchange over patching node_modules. The provider exposes no no-listen mode and package edits would be brittle.
