GitHub auth session hardening

main · worktree /Users/anishthite/workspace/makerspace · 2026-06-18 · status shipped · blast medium

Summary

Goal
Bind GitHub auth to one browser session and block open GitHub-backed access.
Source
Review findings run-mqk89tnj-2, existing GitHub OAuth flow, existing control-token guard.
Surface
/api/auth/github*, /api/github/repos, /api/threads, public/app.js, public/settings.js.
Schema
Remove legacy GitHub fields from data/settings.json; keep browser-session auth in memory only.
Mobile
Untouched.
Open Qs
0.

Algorithm

  1. Generate one browser session id in local storage; send it on GitHub-aware requests.
  2. Store GitHub token/user in server memory keyed by that session id; bind OAuth state to the same session id.
  3. Reject GitHub-aware requests without a browser session id; when CONTROL_API_TOKEN is blank, also require same-origin browser requests.
  4. Use GitHub auth only when the thread came from the repo picker; leave manual public repo URLs alone.

Decisions

IDChoice · Rationale
D-001Use a browser session id header over durable server-side user accounts. Smallest fix that splits browsers cleanly.
D-002Keep GitHub auth in server memory only. Removes the server-global secret file immediately.
D-003Require same-origin browser requests for API routes when CONTROL_API_TOKEN is blank. Blocks credentialless cross-origin reads and writes without breaking token-protected remote deployments.
D-004Bind GitHub-backed threads to the creating browser session. Prevents other browsers from listing, reading, or prompting private workspaces.
D-005Accept GitHub auth only for repos previously loaded into the browser-session repo list. Stops client-only repoSource spoofing from attaching private clone auth to arbitrary URLs.
D-006Bind every browser-created thread to the browser session, not only GitHub-picked threads. Prevents manual private repo URLs from leaking across browsers.

Tradeoffs

IDPicked over Rejected · Reason
T-001In-memory GitHub session over file-backed per-browser sessions. Less code; restart just asks for GitHub reconnect.
T-002Repo-picker-only GitHub auth over auto-enriching every GitHub URL. Avoids turning manual public URLs into auth-coupled failures.

Assumptions

  • A-001 · Losing GitHub auth on server restart is acceptable. If wrong: add durable per-user session storage later.

Reversibility

R-001 · medium. Revert the browser-session header and restore global settings auth; no schema migration blocks rollback.

Definition of done

  • GitHub auth is no longer stored in data/settings.json.
  • Two browsers do not share GitHub identity.
  • GitHub repo listing and private repo thread creation reject cross-origin credentialless calls when CONTROL_API_TOKEN is blank.
  • npm test and npm run build pass.
