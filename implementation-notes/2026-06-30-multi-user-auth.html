Multi-user auth

main · worktree /Users/anishthite/workspace/makerspace · 2026-06-30 · status shipped · blast high

Summary

Goal
Let users sign in with GitHub and see only their sessions, repos, recents, and Pi profile state.
Auth
Use signed HttpOnly cookies plus existing CONTROL_API_TOKEN as admin bypass.
State
Store users, auth sessions, OAuth tokens, and user KV in D1 KV/file fallback; store workspace sessions with ownerUserId.
Git
Clone private repos with a per-user GitHub token and strip raw clone auth before persistence.
Pi
Read/write Makerspace package profile state, not personal ~/.pi/agent, for hosted user flows.
Blast
Auth routing, session visibility, remote sandbox launch, profile sync, static frontend.

API contract

GET /api/me
{ authenticated: boolean, authRequired: boolean, user?: { id, login, avatarUrl }, admin: boolean }
POST /api/auth/github/login
{ loginUrl: string }
POST /api/auth/logout
{ authenticated: false }

Algorithm

  1. Authenticate each API request from CONTROL_API_TOKEN or the signed auth cookie.
  2. Require GitHub login when MAKERSPACE_AUTH_REQUIRED/MAKERSPACE_MULTI_USER is true or hosted GitHub OAuth is configured.
  3. Attach ownerUserId to new sessions and filter all user-visible session routes through the same predicate.
  4. Resolve GitHub repo auth from the signed-in user's encrypted OAuth token during launch only.
  5. Build Pi profile sync payloads from user DB state plus packages/makerspace-pi-defaults.

Decisions

IDChoice · Rationale
D-001GitHub OAuth is the only user sign-in. It already exists for repo access and avoids password storage.
D-002CONTROL_API_TOKEN remains an admin bypass. Existing remote scripts and desktop flows keep a recovery path.
D-003D1/file auth state uses keyed records instead of a new ORM. Existing app state already runs through this layer.
D-004User Pi profiles store overrides in DB and default to packages/makerspace-pi-defaults/context/AGENTS.md. Personal dotfiles stay out of hosted runs.

Tradeoffs

IDPicked over Rejected · Reason
T-001Signed cookies over bearer tokens in localStorage. Session theft blast is lower and logout is server-side.
T-002Per-user GitHub tokens over shared deploy keys. Repo ownership and private clone permissions match the signer.
T-003Admin-only global settings over per-user infra settings. Image/registry/Dockerfile config controls shared backend resources.

Assumptions

  • A-001 · Hosted deployments configure GITHUB_CLIENT_ID, GITHUB_CLIENT_SECRET, and a stable MAKERSPACE_AUTH_SECRET; if wrong: sessions expire on restart or login is disabled.
  • A-002 · Same-origin hosting is acceptable by default; cross-origin static UI can set MAKERSPACE_ALLOWED_ORIGIN and use credentialed requests.

Reversibility

R-001 · high. Revert auth-route changes and ignore ownerUserId; existing session rows remain JSON-readable but visibility semantics return to browser-session/global behavior.

Definition of done

  • GitHub sign-in creates a durable user session.
  • User A cannot list/read/stream/archive User B's sessions without CONTROL_API_TOKEN.
  • Private repo clone auth is generated per launch and not persisted in session output.
  • Pi profile reads/writes avoid personal ~/.pi/agent.
  • npm test and npm run build pass.
