Idle thread sandbox cleanup

main · worktree /Users/anishthite/workspace/makerspace · 2026-07-13 · status shipped · blast medium

Summary

Goal
Free Cloudflare container slots after completed thread sandboxes sit ready beyond a short TTL.
Source
threadBridge sessions with status=ready, unclaimed bridge, and old updatedAt.
Surface
Bridge pruning loop, Cloudflare provider backups, lifecycle docs.
Schema
Add optional stored autoSuspendedAt; no migration.
Open Qs
0.

Algorithm

  1. Keep non-thread reusable bridge cleanup unchanged.
  2. Find remote threadBridge sessions where status/runStatus=ready, bridgeClaimed=false, and idle age exceeds THREAD_BRIDGE_IDLE_TTL_MS.
  3. Call provider.suspendSession() to backup /workspace and pi-sessions, then destroy compute.
  4. Mark the thread suspended with backup refs; users can resume explicitly before the next prompt.

Decisions

IDChoice · Rationale
D-001Auto-suspend over delete. Backups preserve workspace changes while freeing compute slots.
D-002Use a separate thread TTL. Reusable blank bridges and completed thread workspaces have different cost/risk.

Tradeoffs

IDPicked over Rejected · Reason
T-001Explicit resume after auto-suspend over transparent resume-on-prompt. Existing UI already blocks prompts until resume and avoids hidden cold-start work.

Reversibility

R-001 · medium. Set THREAD_BRIDGE_IDLE_TTL_MS=0 or revert cleanup changes; already-suspended threads can be resumed from backups.
