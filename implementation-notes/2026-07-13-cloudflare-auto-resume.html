Cloudflare auto-resume on prompt

main · worktree /workspace · 2026-07-13 · status shipped · blast medium

Summary

Goal
Let a prompt sent to a suspended Cloudflare thread restore the sandbox, reconnect the bridge, and start the run without a separate resume click.
Source
User hit a Cloudflare 1101 Worker HTML page while trying to resume.
Surface
Thread lifecycle service, thread composer state, Cloudflare provider broker errors, Worker broker proxy guard.
Schema
No new fields; existing suspended, launching, ready, and running statuses are reused.
Open Qs
0.

Algorithm

  1. If promptThreadSession() sees a remote thread in suspended, call the existing resume path first with an auto-prompt flag.
  2. Mark resume as launching before the broker call to prevent duplicate resume attempts; roll back to suspended with a warning on failure.
  3. Once the bridge is ready and auth is synced, continue the normal ready-thread prompt start path.
  4. Allow the suspended-thread composer to send and update copy to say send will resume it.
  5. Skip proxyToSandbox() on the broker API host and return JSON if bridge proxy setup throws, so Cloudflare HTML pages do not reach the app.

Decisions

IDChoice · Rationale
D-001Backend auto-resume over frontend chaining two routes. The server owns lifecycle ordering and prevents races even for API clients.
D-002Keep the resume button. Manual resume remains useful, but it is no longer required before the next prompt.
D-003Sanitize provider errors in addition to Worker catch guards. Old deployed Workers can still emit HTML until redeployed.

Reversibility

R-001 · medium. Revert the prompt auto-resume branch and composer copy; suspended threads go back to requiring explicit resume.
