UI layout

  1. Header: use a compact page title, route nav, load status, and one timeline icon anchor.
  2. Controls: group search with a segmented filter for all, active, threads, sessions, archived, and failed rows.
  3. Stats: render six scan cards with semantic tones and stable dimensions.
  4. Rows: render ledger-style cards with a status rail, title, prompt excerpt, repo/branch, dates, restore, and open action.

Decisions

IDChoice · Rationale
D-001Keep the redesign in the existing route runtime. The history API already provides the needed fields.
D-002Use segmented filters over a new sort table. History rows are primarily reopened by status and type.
D-003Use ghost borders and transparent route surfaces. The requested direction matches shadcn card and ghost button defaults.
D-004Move to one shadcn-style panel with divided rows. The page reads cleaner as a Card/Table hybrid than as separate decorative history cards.

Tradeoffs

IDPicked over Rejected · Reason
T-001Ledger cards over a dense table. Prompts and repo paths need wrapping without losing actions.
T-002Neutral borders over colored metric outlines. Status color belongs in labels and dots.
T-003Divided rows over individual row borders. This keeps saved runs scannable while matching shadcn's quieter list density.

Assumptions

  • A-001 · "Full history page" means /history.html. If wrong: move the same visual treatment to the requested history surface.
