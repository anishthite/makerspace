Decisions

IDDecision
D-001Deleted the legacy remote provider file and dependency rather than leaving an env fallback. Rollback is now a git revert, not a runtime switch.
D-002Kept local provider because desktop/local folder mode is not a cloud fallback and does not mask Cloudflare production failures.
D-003Provider talks to a broker over HTTPS because @cloudflare/sandbox needs Worker/Durable Object/Container bindings.
D-004Suspend/delete mean backup then destroy; resume means create then restore. keepAlive=true prevents idle sleep from silently dropping filesystem state between explicit lifecycle actions.
D-005Cloudflare runtime keeps root user identity but stores writable home data under /home/root; no compatibility shim for old /home/daytona cloud paths.
D-006Changed Cloudflare paths to SDK-backup-safe roots: workspace /workspace, home/control under /home/root; /srv and /root are rejected by Cloudflare backup validation.

Tradeoffs

IDTradeoff
T-001Broker exec returns buffered output for provider tools. Upgrade to streaming broker responses only if host-dispatch output latency matters.
T-002KeepAlive costs more than idle sleep, but it is the smallest safe no-fallback path until continuous backup-before-sleep exists.
T-003Session listing returns app-store rows rather than trying to list Durable Objects globally. The app already owns session metadata.
T-004Cloudflare image deploy replaces per-launch custom image building. Settings image fields are ignored for Cloudflare launch until the settings UI is simplified.
T-005Broker uses Cloudflare SDK localBucket backup mode to avoid managing separate R2 S3 credentials. Upgrade to presigned multipart uploads if large repo backups are too slow.

  • R-002 · Session state retains generic sandboxId plus Cloudflare backup handles; old provider-specific fields are no longer written.
