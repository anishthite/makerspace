Summary

Goal
Enable PostHog product events and masked DOM replay for web and Electron.
Source
posthog-js/dist/module.full.no-external for Electron-safe replay.
Surface
frontend/src/entry.jsx, hidden Settings control, thread/workspace runtime events.
Schema
Env-only: VITE_POSTHOG_KEY, VITE_POSTHOG_HOST, VITE_POSTHOG_PROJECT_ID, VITE_POSTHOG_REPLAY_ENABLED, VITE_POSTHOG_DISABLED.
Privacy
Mask prompts, transcripts, tool output, diffs, settings secrets, and repo paths before recording.
Mobile
Same web bootstrap; replay is enabled by env and can be force-disabled by env.
Open Qs
0.

Algorithm

  1. Return no-op when VITE_POSTHOG_KEY is missing or VITE_POSTHOG_DISABLED=1.
  2. Use existing spannerBrowserSession as distinct_id, prefixed by web: or desktop:.
  3. Initialize PostHog with sanitized URLs and enable session recording when VITE_POSTHOG_REPLAY_ENABLED=1, unless local storage explicitly stores spannerPosthogReplayConsent=0.
  4. Capture manual pageviews and safe lifecycle events only.
  5. Keep replay configuration out of Settings; env is the control plane.

Decisions

IDChoice · Rationale
D-001Use the browser SDK in Electron renderer. Spanner desktop is a Chromium app, so DOM replay covers the UI without native capture.
D-002Make replay env-enabled and hide the Settings control per owner request. Keep VITE_POSTHOG_DISABLED and local spannerPosthogReplayConsent=0 as escape hatches.
D-003Sanitize route and event properties at the shared helper. Individual runtime calls stay small.
D-004Preserve PostHog internal properties such as token inside before_send; otherwise the SDK drops events before network send.

Tradeoffs

IDPicked over Rejected · Reason
T-001DOM replay over native screen recording. Native capture adds OS permissions and records unrelated apps.
T-002Direct helper calls over route-level instrumentation framework. Current pages are multi-entry runtime scripts.
