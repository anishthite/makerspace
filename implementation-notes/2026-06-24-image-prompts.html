Image prompts

main · worktree /Users/anishthite/workspace/makerspace · 2026-06-24 · status shipped · blast medium

Summary

Goal
Let users attach images to new and existing thread prompts.
Source
Browser File objects become Pi SDK ImageContent.
Surface
POST /api/threads, POST /api/threads/:name/messages, bridge POST /runs, local Pi runner.
Schema
Add transient images: ImageContent[] to session records during active runs.
Mobile
Composer falls back to stacked controls.
Open Qs
0.

API contract

POST /api/threads
POST /api/threads/:name/messages
{
  prompt: string,
  images?: [{ type: "image", mimeType: "image/png"|"image/jpeg"|"image/gif"|"image/webp", data: base64 }]
}

Bridge POST /runs
{
  id: string,
  prompt: string,
  images?: ImageContent[]
}

Decisions

IDChoice · Rationale
D-001Use Pi SDK PromptOptions.images. Pi already supports image attachments.
D-002Keep attachments inline as base64. Avoid a file-upload store and remote file sync.

Tradeoffs

IDPicked over Rejected · Reason
T-001Browser resize skipped over custom canvas resizing. Server caps keep payloads small.

Reversibility

R-001 · medium. Remove images fields and file inputs to restore text-only prompts.

Definition of done

  • New-thread and existing-thread forms send selected image files.
  • Cloud bridge and local Pi SDK sessions call prompt(text, { images }).
  • npm test passes.
