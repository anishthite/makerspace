Thread resume reconstruction

main · worktree /Users/anishthite/workspace/makerspace · 2026-06-25 · status shipped · blast medium

Summary

Goal
Make follow-up prompts resume the prior Pi conversation instead of starting from only the latest prompt.
Source
User points to Board's SessionManager.open() reconstruction path.
Surface
Host/local Pi runner, bridge payload, generated bridge script, trace files.
Schema
No stored schema change; reuse existing threadMessages[].
Storage
Stable per-thread JSONL files under existing Pi session trace directories.
Open Qs
0.

Algorithm

  1. Use a stable {threadName}.jsonl trace file for each thread.
  2. If that file has real entries, open it unchanged with SessionManager.open().
  3. If the file is missing or header-only, write synthetic message entries from threadMessages[].
  4. Drop the current tail user message before calling session.prompt(prompt).

Decisions

IDChoice · Rationale
D-001Use Pi JSONL over a prompt prefix. Native resume preserves the same context path the SDK expects.
D-002Use threadMessages[] as the cold-start fallback. It already persists user and assistant turns without adding a database.
D-003Skip server mirroring of remote raw trace files. Stable in-bridge traces cover warm bridges; cold bridges get message-level reconstruction.

Tradeoffs

IDPicked over Rejected · Reason
T-001Message-level cold fallback over full remote trace sync. Less network and auth surface for the common follow-up memory fix.
