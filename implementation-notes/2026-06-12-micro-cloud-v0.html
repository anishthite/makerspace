{
  name?: string,

  autoRunAgent?: boolean

POST /api/sessions/:name/share
{
  visibility: "private" | "public",
  sharePort?: number
}
{
  provider: "mock" | "ssh",
  report: { recommendation, rationale, comparison, architecture },
  sessions: [{ name, status, sshDest, httpsUrl, repoUrl, branch, visibility }]
}

Algorithm

  1. Read config; choose ssh when MICRO_CLOUD_PROVIDER=ssh, else choose mock.
  2. Build a setup script that installs base tools, clones the repo or initializes an empty repo, writes helper scripts, and optionally starts pi in tmux.
  3. Call ssh exe.dev new --json --setup-script /dev/stdin; persist request metadata plus returned VM fields in data/sessions.json.
  4. Apply share port and share set-public|set-private when requested.
  5. Serve a static dashboard that posts form data, shows the compare report, and lists sessions with copyable commands.

UI layout

  1. Report cards: show recommendation, when to use exe.dev, when VPS wins.
  2. Launch form: capture repo URL, branch, task prompt, visibility, share port, and auto-run toggle.
  3. Session table: show provider, VM name, status, SSH target, HTTPS URL, and quick actions.

Decisions

IDChoice · Rationale
D-001Use plain Node HTTP plus static files. Avoid framework setup in an empty repo.
D-002Store session metadata in data/sessions.json. Keep v0 state inspectable and file-based.
D-003Expose a control plane, not an in-browser terminal. Ship launch/status first.
D-004Default to exe.dev for v0. It already provides pooled VMs, HTTPS, and SSH-centric automation.
D-005Fallback to a mock provider when live access is unavailable. Keep local iteration unblocked.
D-006Use ssh exe.dev before adding tokenized HTTP. Piping setup scripts via stdin is smaller and matches the official API.

Tradeoffs

IDPicked over Rejected · Reason
T-001ssh exe.dev over tokenized HTTPS. Smaller auth surface and stdin setup-script support.
T-002single-process Node app over split frontend/backend repos. Reduce iteration friction.
T-003prepare-and-optional-run over mandatory auto-run. Pi install/auth details may vary per environment.
T-004forward selected API-key env vars over manual per-VM secret entry. Faster first-run setup at the cost of a rougher secret story.

Assumptions

  • A-001 · pi install command varies; make it env-configurable. If wrong: sessions still provision but need manual install tweaks.
  • A-002 · tmux is acceptable for detached agent runs. If wrong: replace with systemd --user later.
  • A-003 · Local verification will use mock mode because live exe.dev credentials may be unavailable. If wrong: add a live smoke pass.
  • A-004 · Public or cloneable repos are enough for v0. If wrong: add repo upload or sync.

Reversibility

R-001 · medium. Delete generated files; no external schema or irreversible migrations.

Followups
