Codex thread titles

main · worktree /Users/anishthite/workspace/makerspace · 2026-06-24 · status shipped · blast medium

Summary

Goal
Show human-readable thread titles while keeping name as the stable route/session slug.
Source
taskPrompt, repo label, and openai-codex/gpt-5.4-mini via local Pi auth.
Surface
POST /api/threads, GET /api/threads, GET /api/threads/:name, and thread SSE session payloads.
Schema
Add optional session fields title, titleStatus, titleModel, and titleUpdatedAt.
Mobile
Untouched.
Open Qs
0.

Algorithm

  1. Persist an immediate fallback title from the first prompt words before sandbox work starts.
  2. Fire one background completeSimple call with reasoning=minimal, maxTokens=32, and no tools.
  3. Sanitize one line, strip quotes/prefixes, cap at 64 chars, and update only title* fields.
  4. Leave the fallback title when Codex auth, model lookup, timeout, or generation fails.

UI layout

  1. Thread list: render thread.title || thread.name as the primary label.
  2. Thread page: render thread.title || thread.name in the topbar and keep debug data unchanged.

Decisions

IDChoice · Rationale
D-001Keep name immutable and add title. Routes, sandbox names, and existing records stay stable.
D-002Use openai-codex/gpt-5.4-mini by default. It is the cheapest built-in Codex model in this install.

Tradeoffs

IDPicked over Rejected · Reason
T-001Background generation over blocking POST /api/threads. Thread launch latency stays unchanged.
T-002One helper module over wiring a full agent session. A single completion needs no tools or project context.

Assumptions

  • A-001 · Pi Codex auth is present on the server host. If wrong: fallback titles remain.

Reversibility

R-001 · medium. Remove the helper import/calls and ignore optional title* session fields.

Definition of done

  • New threads persist a fallback title immediately.
  • Background Codex success replaces fallback without changing name.
  • Home and thread pages prefer title but still work with old sessions.
  • npm test passes.
