Decisions

IDChoice · Rationale
D-001Use sidebar-scoped control IDs. The global dialog can coexist with workspace and thread composers.
D-002Load model defaults lazily from /api/bootstrap?page=workspace&fast=1. The dialog appears on routes that do not fetch workspace bootstrap.
D-003Keep sidebar prompt submission on /api/threads. The existing endpoint already accepts prompt, model, thinking, project, and images.
D-004Remove shell and section separator strokes; retain one neutral outline strength for interactive controls. The reference uses surface contrast to establish depth.
D-005Keep image previews in the control strip and let its first grid track size to content. Absolute positioning can overlap suggestions.
D-006Submit with Cmd/Ctrl+Enter when the selected project enables the action. Multiline Enter behavior remains unchanged.
D-007Render the image trigger as a real button and click the hidden file input from runtime code. Keyboard navigation must reach the attachment action.
D-008Supersedes the original wide launch scale: cap the dialog at 720px and compress prompt, controls, and suggestions into a utility composer. The sidebar action is frequent and should not dominate the viewport.
D-009Keep project choice prompt-scoped in selectedPromptProject. Changing a run target must not silently switch the surrounding workspace.
D-010Populate the header project select from /api/recent-projects with spannerRecentProjects fallback. Existing project records already contain the request fields.

Tradeoffs

IDPicked over Rejected · Reason
T-001Duplicate sidebar-scoped controls over reusing RunControls. Reusing fixed IDs would create duplicate form control IDs on workspace and thread pages.
T-002Surface contrast over stacked one-pixel separators. Fewer strokes match the reference and avoid doubled edges while the control outlines remain scannable.
T-003Native header select over a nested project modal. Eight recent projects fit the compact interaction and retain keyboard behavior.
