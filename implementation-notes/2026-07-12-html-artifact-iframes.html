HTML artifact iframes

main · worktree /Users/anishthite/workspace/makerspace · 2026-07-12 · status shipped · blast medium

Summary

Goal
When assistant replies mention generated .html artifact paths, show a small inline preview without raw-injecting the HTML into the app DOM.
Source
User asked for inline previews for generated .html artifact paths rendered in sandboxed iframes in chat.
Surface
/thread.html assistant message rendering and artifact file serving.
Schema
No stored data change; one read-only artifact route added.
Open Qs
0; arbitrary HTML stays sandboxed.

Algorithm

  1. Extract only local generated .html artifact paths and cap inline cards at two per message.
  2. Serve the artifact through a thread-scoped route after path normalization and size checks.
  3. Render the response in an iframe with sandbox="allow-scripts", no allow-same-origin, plus a CSP sandbox header.

Decisions

IDChoice · Rationale
D-001Use sandbox="allow-scripts" without allow-same-origin. Interactive mockups can run scripts, but cannot read Spanner origin state.
D-002Limit previews to two per message. Enough for generated mockups; avoids turning chat into an iframe farm.

IDPicked over Rejected · Reason
T-001Small dedicated HTML route over reusing image artifact route. The content type, CSP, and byte cap differ.
