Cloudflare bridge URL fallback

main · worktree /Users/anishthite/workspace/makerspace · 2026-07-14 · status ready-for-review · blast low

Summary

Goal
Return a usable stable bridge URL even when the broker request arrives on a workers.dev hostname.
Source
@cloudflare/sandbox port exposure plus the routed spanner.sh bridge wildcard.
Surface
POST /sessions/:id/ports/:port broker route and Cloudflare provider launch path.
Schema
None.
Open Qs
0.

Algorithm

  1. Pick CLOUDFLARE_SANDBOX_PORT_HOSTNAME when set.
  2. Map sandbox.spanner.sh to spanner.sh; map *.workers.dev to spanner.sh.
  3. Use exposePort().url when present; otherwise synthesize https://{port}-{id}-bridge.{hostname}.
  4. Await broker route handlers inside the fetch error guard so async SDK failures return JSON instead of Worker 1101.
  5. Fail provider launch with an actionable broker-url hint if the broker still returns no URL.

Decisions

IDChoice · Rationale
D-001Default workers.dev broker requests to spanner.sh. The Worker already routes *-bridge.spanner.sh and workers.dev cannot serve wildcard bridge hosts.
D-002Synthesize stable URLs with token bridge. The broker already uses that stable token for exposePort().
D-003Drop the tunnels fallback. The broker uses HTTP transport and the SDK requires RPC for that API.

Tradeoffs

IDPicked over Rejected · Reason
T-001Worker URL fallback over another backend retry. Empty URL is deterministic configuration/SDK output, not a boot delay.
T-002Provider guard over letting waitForBridge() throw. The guard points at the broker hostname setting.

Reversibility

R-001 · low. Revert the worker helper import, provider guard, and tests; no stored data changes.
