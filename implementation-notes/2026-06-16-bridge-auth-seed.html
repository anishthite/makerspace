Algorithm

  1. Self-elevate the exe.dev setup script with sudo when it starts as an unprivileged user.
  2. After VM provisioning, copy local ~/.pi/agent/auth.json into the VM over bootstrap SSH before starting the bridge run.
  3. Wait for bridge health, then start the Pi SDK run as before.
  4. Fix the bridge stream route to read streamMatch[1], not runMatch[1].

Decisions

IDChoice · Rationale
D-001Copy local auth at launch time instead of baking secrets into the image. Keeps the secret out of image layers.
D-002Use one extra bootstrap SSH write to the VM. User already accepts SSH for provisioning/bootstrap.
D-003Stop on a real end-to-end success signal, not just green unit tests. The breakages were runtime-only.

Tradeoffs

IDPicked over Rejected · Reason
T-001runtime auth seeding over bake keys into image. Safer and easier to rotate.
T-002copy full auth.json over translate OAuth tokens to env vars. Smaller diff; Pi already knows how to read its own auth file.

Reversibility

R-001 · medium. Remove the auth copy step and the sudo preamble when a proper custom image or secret-delivery path exists.
