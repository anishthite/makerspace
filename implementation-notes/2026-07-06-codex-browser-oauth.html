Browser OAuth for provider sign-in

main · worktree /Users/anishthite/workspace/makerspace · 2026-07-06 · status shipped · blast medium

Summary

Goal
Make Settings sign-in use browser OAuth for openai-codex and anthropic instead of Codex device-code numbers.
Source
User request: remove the device-code flow for both provider sign-ins and push.
Surface
POST /api/auth/openai-codex/login, POST /api/auth/openai-codex/login/:id/code, /settings.html#codex, /settings.html#claude-code.
Schema
None; stored OAuth credentials keep the existing per-user secret keys.
Open Qs
0.

API contract

Request

POST /api/auth/openai-codex/login/:id/code
{ "code": "http://localhost:1455/auth/callback?code=..." }

Response

{ id: string, status: "exchanging" | "complete" | "failed", auth: object | null, manual: boolean }

UI layout

  1. Codex: open the browser authorization URL and show one pasted redirect/code input.
  2. Claude Code: keep the existing browser authorization URL and pasted redirect/code input.

Decisions

IDChoice · Rationale
D-001Prefer the provider option whose id or label says browser. Pi already exposes browser OAuth as the Codex default.
D-002Use pasted redirect/code fallback for hosted runs. The OAuth redirect target is localhost and may be on the user machine, not the backend.
D-003Tell users to copy the localhost error-page URL. That URL is the expected hosted fallback input.

Tradeoffs

IDPicked over Rejected · Reason
T-001One provider-login helper over separate Codex and Claude Code flows. It keeps both sign-ins on the same non-device behavior.
