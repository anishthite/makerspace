Inline PNGs in HTML replies

main · worktree /Users/anishthite/workspace/makerspace · 2026-07-03 · status shipped · blast low

Summary

Goal
Render assistant-mentioned .png/.svg/.webp/.gif/.jpg paths inline when the assistant message is an HTML fragment.
Bug
renderMessageBody used includeImages: false for all HTML previews, so path-only image mentions never became image cards.
Source
User asked why artifacts/workflow-rail-preview.png did not render inline.
Surface
/thread.html assistant message rendering.
Schema
No data change.
Open Qs
0.

Algorithm

  1. Detect safe relative image paths already embedded as HTML <img src>.
  2. Render normal image artifact cards for path mentions in HTML replies.
  3. Skip only the embedded <img src> paths to avoid duplicate cards.

Decisions

IDChoice · Rationale
D-001Filter embedded <img src> paths instead of disabling all image cards. HTML replies can contain plain path mentions outside image tags.
D-002Keep the existing diagram-image intent filter. It prevents generic logo/static asset mentions from rendering as cards.

Tradeoffs

IDPicked over Rejected · Reason
T-001Small path filter over a new attachment protocol. The existing artifact route and card UI already solve image display.
