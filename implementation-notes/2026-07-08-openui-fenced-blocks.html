Decisions

IDChoice · Rationale
D-001Use openuiChatLibrary. Inline thread messages need a single vertical card, not free dashboard layout.
D-002Keep workbench-ui unchanged. Existing small controls still cover simple composer actions.
D-003Disable OpenUI tool provider. Workbench should not execute model-declared UI tools in the browser.
D-004Prefer openui over hand-authored HTML in Workbench default prompts. The renderer now exists and gives structured cards/tables/charts without sandboxed HTML fragments.
D-005Force openui for final Workbench answers by default. The experiment is reversible in one prompt file if rendered cards feel heavy.
D-006Remove Workbench's OpenUI wrapper chrome. OpenUI output should feel like the answer body, not a nested artifact card.
D-007Pair openui answers with one optional workbench-ui control panel. Tunable next turns need sliders/checklists more than prose.

Tradeoffs

IDPicked over Rejected · Reason
T-001Imported OpenUI over porting components. Reimplementation creates maintenance debt immediately.
T-002Plain fence regex over a markdown AST. Existing artifact renderers already use bounded fence extraction.

Deviations

IDFrom · Did · Reason
X-001Static renderer import · Switched to dynamic import · Keeps the normal thread chunk small when no openui fence exists.
X-002Strict root = requirement · Normalize bare component calls to root = ... · OpenUI parses bare calls without throwing but renders no root, which creates a confusing user error.
