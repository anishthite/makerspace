Algorithm

  1. Keep GET /api/threads/:name/diff and existing file-chip selection.
  2. Strip the existing truncation suffix before parsing unified patches.
  3. Dynamic-import @pierre/diffs only when the dialog opens.
  4. Parse with processPatch(diffText, undefined, true) so stale cache keys cannot reuse old diff text.
  5. Render each parsed FileDiffMetadata through vanilla new FileDiff(...).render().
  6. Fall back to renderPlainDiff() on parser/import errors or non-unified previews.

UI layout

  1. #diff-dialog: native dialog, flat dark plane, tiny path title, plain close action.
  2. #diff-dialog-files: hidden for single-file diffs; shown only when it enables multi-file navigation.
  3. .pierre-diff-list: one stacked column inside the dialog body.
  4. diffs-container: Pierre shadow-DOM surface without extra border, shadow, or nested card frame.

Decisions

IDChoice · Rationale
D-001Use vanilla FileDiff. The thread runtime is plain DOM code, so a React bridge would add a second render path.
D-002Keep unified layout. It matches the existing compact dialog and avoids side-by-side width tuning.
D-003Do not pass a Pierre cache key prefix. Thread diffs mutate under the same session name.
D-004Use unsafeCSS only for Pierre's shadow DOM. The outer dialog stays normal route CSS.
D-005Keep code mono instead of applying the paper-style serif literally. Diff readability beats the style preset.
D-006Use UI Skills baseline-ui, better-ui, and distill. The selected pass removes visual noise instead of adding another decorative treatment.

Tradeoffs

IDPicked over Rejected · Reason
T-001FileDiff over CodeView. Current dialog already slices selected files; CodeView is only worth it if huge diffs lag.
T-002Lazy Pierre/Shiki chunks over keeping diff2html. The UI improves, but the build emits many syntax assets.
T-003Quiet dark frame over decorative paper treatment. The surface is a code-review tool, not a reading artifact.
T-004Single flat code plane over nested modal/card/file surfaces. Kept only necessary change coloring, title, close control, and multi-file navigation.
