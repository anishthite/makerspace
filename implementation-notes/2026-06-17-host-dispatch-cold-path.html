Summary

Goal
Make direct cold POST /api/chat start the actual Pi provider request under 1000 ms.
Rejected prior
2026-06-17-intent-prelaunch.html proved a prepared bridge path, not true cold submit.
Approach
Run the Pi SDK on the app server immediately with remote-tool definitions that wait for the new exe.dev VM only when tools execute.
Measurement
Use direct scripts/measure-bootup.js with isolated SESSION_DATA_PATH, WARM_BRIDGE_POOL_SIZE=0, and no --intent-prep.
Open Qs
0.

Algorithm

  1. Accept POST /api/chat; create one stored session and start host Pi dispatch immediately.
  2. Wrap piSession.agent.streamFn; persist first_llm_call_start before the provider request leaves the host process.
  3. Provision the exe.dev VM concurrently with autoRunAgent=false so setup creates the same workspace and bridge but does not start a second Pi run.
  4. Expose remote proxy tools with the standard Pi tool names; tool execution awaits VM readiness and runs against /srv/workspace.
  5. Stream host Pi SDK events through the existing session SSE endpoints.

Decisions

IDChoice · Rationale
D-001Start Pi SDK on the app server for cold submit. VM provisioning cannot physically finish under 1000 ms.
D-002Proxy standard Pi tools to the new VM when they execute. The first LLM request sees normal tool availability while tool effects remain remote.
D-003Remove browser submit gating. Normal submit must be measurable without hidden prep state.

Tradeoffs

IDPicked over Rejected · Reason
T-001Host provider call with remote tool proxies over prepared bridge. It satisfies the true cold metric without a pool.
T-002Tool execution waits for VM readiness over failing early. Correctness beats instant tool failure.

Reversibility

R-001 · medium. Disable host dispatch to return fresh chats to bridge-only VM execution; cold submit latency returns to VM provisioning time.

Definition of done

  • Normal browser submit posts directly to /api/chat without automatic /api/bridge-intents.
  • Fresh /api/chat starts an actual Pi SDK provider request under 1000 ms.
  • Pi tool names remain available and execute against the provisioned VM.
  • Direct cold measurement from empty stored sessions passes without --intent-prep.
  • npm test passes.
