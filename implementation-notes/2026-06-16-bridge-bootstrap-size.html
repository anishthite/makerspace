Summary

Goal
Keep ssh exe.dev new --setup-script /dev/stdin below exe.dev's 10 KiB input limit.
Source
Real launch failed with --setup-script=/dev/stdin: input exceeds 10 KiB limit.
Surface
src/setup-script.js, test/setup-script.test.js, this note.
Schema
None.
Runtime
Bridge still writes the same pi-bridge.mjs; only the bootstrap transport changes.
Open Qs
0.

Algorithm

  1. Generate the bridge source as a normal JavaScript string inside src/setup-script.js.
  2. Compress it with gzipSync(...).toString('base64') at setup-script build time.
  3. Emit a short shell heredoc that runs base64 -d | gzip -d > /srv/micro-cloud/pi-bridge.mjs on the VM.
  4. Keep tests extracting and gunzipping the payload so they still inspect the real bridge source.

Decisions

IDChoice · Rationale
D-001Compress the bridge payload instead of adding a second SSH bootstrap phase. Keeps SSH limited to the one exe.dev launch call.
D-002Test size at the generated-script boundary. The failure is about bytes sent to exe.dev, not source-file length.

Tradeoffs

IDPicked over Rejected · Reason
T-001gzip + base64 heredoc over plain inline JS. Same behavior, smaller transport.
T-002compressed inline payload over post-boot SSH file copy. Fewer moving parts in the launch flow.

Reversibility

R-001 · medium. Restore the plain heredoc bridge payload if exe.dev lifts the input limit or if compressed bootstrap proves harder to debug.

Definition of done

  • Bridge chat setup scripts fit under 10 KiB.
  • Tests still inspect the decoded bridge source.
  • npm test passes.
