Summary

Goal
Show changed files and a selected-file diff directly under the agent rail.
Source
git status --porcelain and git diff HEAD from the thread workspace.
Surface
GET /api/threads/:name/diff and /thread.html.
Schema
No stored data change.
Mobile
Diff box stacks inside the existing agent rail.
Open Qs
0; assume read-only diff editor until save/edit is requested.

API contract

Request

GET /api/threads/:name/diff

Response

{
  generatedAt: string,
  status: string,
  diff: string,
  files: [{ path: string, code: string, label: string }],
  truncated: boolean,
  notGit: boolean
}

Algorithm

  1. Resolve the thread and enforce the existing browser-session access check.
  2. Run the same capped git script in repoPath for local threads or remoteWorkspaceDir through the provider for bridge threads.
  3. Parse porcelain status into file chips and split the unified diff client-side for the selected editor pane.

UI layout

  1. Diff box: render native <details> directly under #agent-rail.
  2. File rail: show changed file chips with short status labels.
  3. Editor: show the selected file diff in a read-only native <textarea>.

Decisions

IDChoice · Rationale
D-001Use native git output. It avoids a diff parser dependency and matches developer expectations.
D-002Use a read-only <textarea>. It is the lightest performant editor for viewing diffs.
D-003Cap diff bytes server-side. The rail must not try to render a repo-sized patch.

Tradeoffs

IDPicked over Rejected · Reason
T-001Read-only workbench over save-capable file editing. The request needs visibility into changes, not mutation.
T-002Route polling after tool events over a live file watcher. Existing events already tell the page when work likely changed files.
