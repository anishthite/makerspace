Summary

Goal
Show cached GitHub repos immediately and refresh the full repo index in the background.
Source
githubRepos cached in user KV or browser session after prior /api/github/repos calls.
Surface
/, /workspace.html, /api/auth/github, /api/bootstrap?page=project, /api/bootstrap?page=workspace.
Schema
No persisted shape change; expose cache metadata in existing JSON responses.
Open Qs
0; treat “initial loading state quicker” as first usable repo picker after auth resolves.

API contract

Response fragment

{
  github: {
    repos: GitHubRepo[],
    repoCache: { count: number, cached: boolean }
  }
}

Algorithm

  1. Read cached repos while computing public GitHub auth status.
  2. Render cached repos before invoking /api/github/repos.
  3. Refresh all repo pages in the background and replace the cache when complete.

Decisions

IDChoice · Rationale
D-001Expose cached repos on auth payloads. The frontend already waits for auth before repo loading.
D-002Keep full pagination in /api/github/repos. A complete index is still needed for long-tail repo search.

Tradeoffs

IDPicked over Rejected · Reason
T-001Cached-first hydration over server-side partial pagination. It improves first paint without changing GitHub API semantics.
