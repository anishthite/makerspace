Summary

Goal
Let background Workflow results appear in the thread and trigger their automatic follow-up turn.
Source
A Workflow run reports Workflow started... but the bridge closes the SDK session before the background completion calls pi.sendMessage(..., triggerTurn: true).
Surface
src/setup-script.js, test/setup-script.test.js, implementation-notes/INDEX.html.
Runtime
Generated VM bridge only; browser/server SSE envelope stays unchanged.
Open Qs
0.

Algorithm

  1. Detect background tools from tool_execution_end result details or the Workflow start text.
  2. Publish visible custom messages from message_end when extensions emit displayable custom content.
  3. After the initial prompt resolves, keep the SDK session subscribed until a post-background agent_end happens or a bounded idle timeout expires.
  4. Publish bridge completed only after the continuation window closes.

Decisions

IDChoice · Rationale
D-001Patch the bridge lifecycle instead of the Workflow extension. The extension already emits a follow-up when kept alive.
D-002Use a bounded wait. The bridge should not hold a thread forever if a background run stalls.

Tradeoffs

IDPicked over Rejected · Reason

Reversibility

R-001 · medium. Remove the continuation wait and custom-message publishing if long-lived bridge runs block normal follow-up prompts.
