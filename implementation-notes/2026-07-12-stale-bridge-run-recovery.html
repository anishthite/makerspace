Stale bridge run recovery

main · worktree /Users/anishthite/workspace/makerspace · 2026-07-12 · status shipped · blast medium

Summary

Goal
Stop remote threads from staying running after the bridge loses the run or only emits heartbeats.
Source
Bridge SSE events from /runs/:id/stream.
Surface
src/server/bridge.js, Cloudflare backup provider, thread stop path.
Schema
Add optional stale markers and backup-error fields to session JSON.
Storage
Persist assistant text, terminal failure, and best-effort Cloudflare backups for reachable stale sandboxes.
Open Qs
0.

Algorithm

  1. Reset stream retry timers only from parsed JSON events, not SSE comment heartbeats.
  2. Track lastRealEventAtMs per followed bridge run.
  3. If stream reconnects return 404, mark the thread failed/stale immediately.
  4. If now - lastRealEventAtMs > PI_BRIDGE_RUN_STALE_MS, mark failed/stale after best-effort backup.
  5. Persist partial assistant output before the terminal stale update.

Decisions

IDChoice · Rationale
D-001Mark stale runs as failed with staleAt. Existing UI already understands terminal failures.
D-002Use best-effort Cloudflare backups before stale failures. Reachable sandboxes can preserve workspace and Pi traces.
D-003Keep backup failures in staleBackupError. A missing sandbox should not block terminalizing the thread.
