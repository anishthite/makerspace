Step-by-step plan

  1. Measure current Daytona phases with bridgeLaunchLog; keep this as the before baseline.
  2. Add INFRA_PROVIDER=cloudflare behind the existing provider factory; do not remove Daytona.
  3. Create a small Cloudflare Worker broker with export { Sandbox } from "@cloudflare/sandbox", proxyToSandbox(), one Durable Object binding, one container binding, and broker-token auth.
  4. Port Board's CloudflareSandboxClient pattern into the broker: getSandbox(binding, id, { transport: "http", enableDefaultSession: false, normalizeId: true, sleepAfter: "30m" }).
  5. Build a Spanner sandbox image from Cloudflare's base with Node, git, gh, Pi, spanner-pi-defaults, and the bridge runner preinstalled; make setup a health check, not an installer.
  6. Implement the provider minimum: createSession, listSessions, destroySession, runRemoteScript, readRemoteFile, writeRemoteFile, remoteAccess, setShare, and bridgeHeaders.
  7. Map paths to provider-neutral config: CLOUDFLARE_HOME=/root, CLOUDFLARE_CONTROL_DIR=/root/.spanner/control, CLOUDFLARE_WORKSPACE_DIR=/srv/workspace; remove Daytona path assumptions from shared routes.
  8. Return Cloudflare preview URLs from exposePort(4310); keep Spanner bridge bearer auth as the real access control.
  9. Persist cross-sleep state before enabling sleep: backup /srv/workspace, /root/.spanner/control/pi-sessions, and required Pi profile/auth state; exclude secrets and generated dependency folders.
  10. Restore backup handles on createSession for existing threads; treat local container disk as a cache like Board treats /root/.pi/sessions.
  11. Add startup debug rows matching Board: create, restore, setup, expose-port, bridge-health, first bridge event, first LLM call.
  12. Shadow-run one internal thread with INFRA_PROVIDER=cloudflare; compare time-to-ready, first LLM latency, tool exec latency, file read/write, artifact preview, and draft PR creation.
  13. Canary hosted users behind SPANNER_CLOUDFLARE_CANARY_USERS; keep Daytona as fallback per session.
  14. Flip the default only after canary passes: INFRA_PROVIDER=cloudflare, CLOUDFLARE_INSTANCE_TYPE=standard-2, CLOUDFLARE_SLEEP_AFTER=30m, WARM_BRIDGE_POOL_SIZE=0.
  15. Keep Daytona provider for durable workspace mode until Cloudflare backup/restore survives a full suspend/resume/delete cycle.

Decisions

IDChoice · Rationale
D-001Use a Worker broker instead of importing @cloudflare/sandbox into the Node backend. Sandbox needs Worker Durable Object and Container bindings.
D-002Keep Spanner's existing Pi bridge. It already solves browser streaming, auth, tool execution, and follow-up turns.
D-003Start with transport: "http". Board found the RPC control-connection upgrade path brittle.
D-004Use a baked image. Board removed runtime file writes and npm installs from startup; Spanner should not repeat that mistake.
D-005Use D1/session-store plus R2 backups as source of truth. Cloudflare container disk is a cache after sleep.
D-006Canary before default switch. Provider bugs affect auth, git writes, and user repo state.

Tradeoffs

IDPicked over Rejected · Reason
T-001Broker sidecar over full backend migration to Workers. It preserves the Node control plane and deletes less code.
T-002Backup/restore over keepAlive=true. Sleep saves money; keepAlive hides persistence bugs and burns idle spend.
T-003standard-2 default over standard-3. Most Spanner work waits on LLMs and short test bursts; upgrade only when repos prove large.
T-004Daytona fallback over big-bang cutover. Existing workspace persistence is safer while Cloudflare persistence is being proven.

Assumptions

  • A-001 · Cloudflare account has Workers Paid, Containers, R2, and Durable Objects enabled; if wrong, broker deploy blocks before app changes.
  • A-002 · Spanner bridge works over Cloudflare exposePort(4310) with SSE; if wrong, host-dispatch can still validate tool execution first.
  • A-003 · R2 backups of workspace plus Pi session files are enough for follow-up continuity; if wrong, add D1-backed Pi JSONL replay like Board.

Reversibility

R-001 · high. Set INFRA_PROVIDER=daytona and leave Cloudflare broker deployed but unused.

Followups

  • L-001 · Re-test Cloudflare transport: "rpc" after the broker is stable.
  • L-002 · Add an automated launch benchmark that compares Daytona and Cloudflare on the same repo and prompt.

Definition of done

  • Cloudflare can launch a fresh Spanner thread and reach bridge health.
  • Remote tools pass bash, read, write, edit, artifact preview, and draft PR smoke checks.
  • A stopped/slept Cloudflare thread restores workspace and Pi context.
  • Startup timings prove Cloudflare beats the measured Daytona path for typical Makerspace repos.
  • Hosted default can flip back to Daytona with one env var.
