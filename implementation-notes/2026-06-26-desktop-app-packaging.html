Summary

Goal
Build Makerspace.app so Electron loads desktop/main.js, not default_app.asar.
Source
User asks for the packaged app to open as Makerspace.
Surface
npm run desktop:package, macOS app bundle metadata, bundled backend launch.
Schema
No data schema change.
Open Qs
0.

Algorithm

  1. Copy node_modules/electron/dist/Electron.app to output/desktop-package/Makerspace.app.
  2. Remove Resources/default_app.asar; copy app sources to Resources/app.
  3. Set CFBundleExecutable, CFBundleName, CFBundleDisplayName, and CFBundleIdentifier.
  4. Use the packaged Electron binary with ELECTRON_RUN_AS_NODE=1 for the local backend.
  5. Create a DMG when hdiutil is available.

Decisions

IDChoice · Rationale
D-001Use Electron manual distribution. It fixes the current default-app bundle without adding Electron Builder.
D-002Copy source directories instead of making app.asar. Easier to inspect and enough for local testing.
D-003Use ELECTRON_RUN_AS_NODE=1 when packaged. Avoid requiring users to have node on PATH.

Tradeoffs

IDPicked over Rejected · Reason
T-001Keep Electron helper branding over full helper bundle renames. Main app identity is the blocker; helper renames are signing-sensitive.
T-002Ad-hoc signing over Developer ID signing. Local package smoke works without certificate setup.

Assumptions

  • A-001 · macOS packaging runs on macOS with plutil; Linux/Windows packaging stays out of scope.
