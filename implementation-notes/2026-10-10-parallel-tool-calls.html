Parallel tool calls

parallel-tool-calls · makerspace-parallel-tool-calls · 2026-10-10 · ready-for-review · medium

Summary

GoalRun independent file calls concurrently without reordering dependent effects.
SurfaceAgent batches and correlated terminal events.
DependenciesStandard library only.

Algorithm

  1. Partition the call list at Bash or unclassifiable calls; execute those barriers exclusively.
  2. Resolve file identities at each parallel segment, preserving same-file and ancestor/descendant call order through completion channels.
  3. Run independent calls concurrently; serialize event callbacks and append results in original call order.
  4. Join every worker before returning cancellation; provide one result for every call.

Decisions

IDChoiceReason
D-001Use batch-local completion dependencies instead of a persistent lock registry.The agent permits only one active batch.
D-002Run Bash exclusively against all calls, including reads.Shell effects cannot be attributed to one path.
D-003Serialize conflicting reads as well as writes in model order.A read after an edit must observe the edit.
D-004Resolve symlink ancestors and compare existing hardlink identities.Different spellings must not race on the same file.

Tradeoffs

T-001Serialize same-file reads instead of reader/writer scheduling; preserve a small scheduler.

Assumptions

  • A-001 · External processes can still mutate the workspace; these dependencies coordinate only this agent batch.

Reversibility

R-001 · Medium: concurrent independent tool effects; leave changes isolated on the new branch and revert its batch dispatch to restore sequential execution.

Definition of done

  • Independent file calls overlap; same-path aliases and Bash barriers retain order.
  • Results retain call order; events contain IDs and callbacks never overlap.
  • Cancellation resolves all calls and joins running workers.
  • Full tests, race tests, vet, and build pass.
