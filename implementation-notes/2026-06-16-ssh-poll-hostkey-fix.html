ssh poll hostkey fix

nogit · worktree /Users/anishthite/workspace/makerspace · 2026-06-16 · status shipped · blast medium

Summary

Goal
Stop fresh VM output polling from hanging on SSH trust prompts or early reachability blips.
Source
User hit a timed out after 15000ms poll error and saw the server ask whether to trust the host.
Surface
src/provider.js, test/provider.test.js.
UI
Keep the transcript in a loading state until SSH is actually reachable.

Algorithm

  1. Add shared SSH args with StrictHostKeyChecking=accept-new.
  2. Use a short connect timeout for per-VM output polling.
  3. Treat timeout/refused/unresolved poll failures as transient; keep polling instead of surfacing a hard error.

Files

PathKindDelta
src/provider.jstouchAdd SSH option helpers and transient poll error handling.
test/provider.test.jstouchAssert SSH args include auto-accept and transient error detection works.

Decisions

IDChoice · Rationale
D-001Use accept-new instead of disabling host-key checks. Removes the prompt without throwing SSH trust away entirely.
D-002Classify early reachability failures as transient. Fresh VMs often exist before SSH is ready.

Reversibility

R-001 · medium. Remove the SSH options helper and transient classifier to return to strict manual trust prompts.

Definition of done

  • Fresh VM polling no longer asks for interactive trust confirmation.
  • Transient SSH readiness errors do not show as final chat failures.
  • Tests pass.
