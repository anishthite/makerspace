Summary

Goal
Persist agent trace events so reopened threads show full tool/thinking/workflow history after reloads and restarts.
Source
Existing recordRunEvent() stream events and bridge/local Pi events.
Surface
GET /api/sessions/:name/output, GET /api/sessions/:name/stream, /thread.html trace timeline.
Schema
Add a bounded trace sidecar keyed by session.name with monotonic nextId; use makerspace_kv when MAKERSPACE_STATE_STORE=d1.

API contract

GET /api/sessions/:name/output
{
  session: Session,
  chunk: string,
  runStatus: string,
  warning: string | null,
  events: TraceEvent[]
}
GET /api/sessions/:name/stream?after=<id>
SSE event id = durable TraceEvent.id

Algorithm

  1. Initialize each run's nextEventId from durable nextId instead of resetting to 1.
  2. Normalize every trace-worthy event in recordRunEvent(): id, timestamp, runId, type, payload, sequence.
  3. Append normalized events to the in-memory run and to durable storage before notifying SSE subscribers when practical; preserve live delivery if disk/D1 write stalls.
  4. On /output, merge durable historical events with live events by id and return one de-duplicated ordered list.
  5. On /stream?after=N, replay durable/live events with id > N, then subscribe to live updates.
  6. Cap retention per session by event count and payload bytes; keep full assistant text in existing output/message storage.

UI layout

  1. Trace timeline: render durable events through existing renderEvent(); no second UI path.
  2. Run markers: keep current runtime marker behavior and open the same hydrated #agent-trace.
  3. Partial history: show a small trace notice only if old events exceed the retention cap.

Decisions

IDChoice · Rationale
D-001Persist event logs, not rendered HTML. The existing renderer remains the only projection.
D-002Use monotonic durable event IDs per session. SSE replay and UI de-duplication already use IDs.
D-003Persist only structured trace events and capped tool output snippets. Assistant transcript already has separate durable storage.
D-004Support D1 through makerspace_kv. Remote deployments should keep trace history with session state.

Tradeoffs

IDPicked over Rejected · Reason
T-001Sidecar trace store over stuffing sessions.json. High-volume trace events should not bloat the session index.
T-002JSON sidecar/D1 KV over SQLite. Current app already uses JSON stores and optional D1 state.
T-003Bounded retention over infinite traces. Tool output can be large and already truncates in the UI.

Assumptions

  • A-001 · Durable history means tool/thinking/workflow/log/status trace, not unlimited raw stdout; if wrong: raise retention or add an export endpoint.
  • A-002 · Per-session sidecar files are acceptable beside data/sessions.json; if wrong: store compact traceEvents directly on session rows.
  • A-003 · D1 KV payload size is enough for capped trace history; if wrong: add a dedicated makerspace_trace_events table.

Reversibility

R-001 · medium. Revert trace-store calls and ignore sidecar files; existing session/chat history remains readable.

Definition of done

  • Trace events survive browser reload and server restart.
  • Active SSE reconnect replays missed durable events with no duplicates.
  • Archived/completed thread pages show historical trace cards.
  • node --test test/trace-store.test.js test/thread-trace-tray.test.js passes.
  • npm test and npm run build pass.
