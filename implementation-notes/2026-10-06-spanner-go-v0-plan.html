Spanner Go v0 plan

Summary

Goal
Build a local Go coding-agent harness with a bounded tool-use loop and a minimal terminal UI.
Source
context-labs/whip@whip-v1: agent.go, tools.go, run.go, and Bubble Tea TUI architecture.
Surface
spanner "prompt" plus the interactive Bubble Tea session.
Provider
One OpenAI-compatible HTTP endpoint configured by environment variables.
Tools
bash, read, write, and edit.
State
In-memory conversation only; no session persistence or config file.
UI
Bubble Tea transcript, prompt textarea, streamed text, and compact tool rows.
Open Qs
0.

API contract

spanner [--max-turns N] "prompt"

OPENAI_API_KEY   required
OPENAI_BASE_URL  optional; OpenAI-compatible chat-completions base URL
OPENAI_MODEL     required

Algorithm

  1. Append the user prompt to in-memory conversation state.
  2. Send the conversation and four tool schemas to the configured endpoint.
  3. Stream assistant text to the terminal model; append the completed assistant message.
  4. Execute emitted calls sequentially; append each result as a tool message.
  5. Repeat until the model emits no calls or --max-turns is reached.

UI layout

  1. Transcript: viewport of user prompts, assistant text, and tool status rows.
  2. Composer: textarea for a single prompt submission.
  3. Lifecycle: Ctrl-C cancels active work; Ctrl-D exits.

Decisions

IDChoice · Rationale
D-001Copy Whip’s loop and four core file/code tools. They are the smallest reliable coding-agent surface.
D-002Use one OpenAI-compatible endpoint. A direct net/http client avoids provider routing and SDK surface.
D-003Use Bubble Tea with textarea, viewport, and Lip Gloss. It fits streaming terminal chat without copying Whip’s coupled TUI.
D-004Execute calls sequentially. Parallelism needs file mutation locks and adds no v0 requirement.

Tradeoffs

IDPicked over Rejected · Reason
T-001Dedicated read/write/edit over bash-only. Structured file mutations are more reliable for models.
T-002Fresh one-file-scale Bubble Tea screen over copying Whip’s internal/tui. Whip’s UI imports its full runtime platform.
T-003In-memory conversation over sessions and compaction. A short v0 run needs neither persistence nor history management.

Assumptions

  • A-001 · Run only in a user-trusted local repository. If shared/untrusted execution is required, add explicit permission gates first.

Reversibility

R-001 · low. Delete the additive Go files and this plan; existing retained repository metadata stays unchanged.

Followups

  • L-001 · Add session persistence, permission UX, and parallel mutation locks only after the v0 loop is proven.
  • L-002 · Add MCP, LSP, subagents, model catalogs, browser automation, and compaction only when a concrete use case requires each.

Definition of done

  • go test ./... verifies model → tool → final-answer looping.
  • Configured spanner "list this repository" renders streamed text and tool rows.
  • Cancellation stops an active HTTP request or command cleanly.
  • v0 contains none of the deferred integration or persistence surfaces.
