API contract

Artifact

```makerspace-ui
{
  "version": 1,
  "title": "Tune this answer",
  "controls": [{ "id": "detail", "type": "slider", "label": "Detail", "min": 1, "max": 10, "default": 5 }],
  "actions": [{ "id": "apply", "label": "Apply", "delivery": "followUp", "prompt": "Revise with detail={{detail}}." }]
}
```

Action output

[UI action: Apply]
Revise with detail=7.

Excalidraw save

POST /api/threads/:name/artifacts?path=diagram.excalidraw
{
  "type": "excalidraw",
  "elements": [],
  "appState": {},
  "files": {}
}

Algorithm

  1. Extract complete fenced makerspace-ui blocks from raw assistant text.
  2. Validate version, IDs, counts, lengths, control types, action types, and delivery allowlist.
  3. Render controls as Makerspace DOM after message attachments and diagram cards.
  4. Fill the composer with generated prompt text; user sends the visible message.
  5. Expose diagram prompt actions from inline Excalidraw cards.
  6. Save trusted editor changes through the existing artifact route after path, session, type, and size checks.

UI layout

  1. Artifact card: title, optional description, control groups, action row.
  2. Controls: slider with live output, checklist, select, text area, buttons.
  3. Action: fill composer first and show requested delivery mode through existing composer behavior.
  4. Diagram card: show open, edit, and scoped prompt-action buttons.
  5. Editor: open explicit full-page Excalidraw editor with save status and thread link.

Decisions

IDChoice · Rationale
D-001Use fenced makerspace-ui JSON. It is parseable without trusting assistant HTML.
D-002Fill the composer instead of auto-sending. The user sees every generated prompt before it leaves.
D-003Keep widget state in the rendered message only. The transcript stays the durable record.
D-004Add diagram prompt buttons before automating diagram edits. Prompted edits keep workspace changes auditable.
D-005Use a separate excalidraw-editor.html route for writes. Normal assistant previews stay no-JS and read-only.
D-006Render makerspace-ui controls only for HTML-mode assistant messages. Plain-text turns keep literal artifact fences visible.

Tradeoffs

IDPicked over Rejected · Reason
T-001Vanilla DOM over React/Radix. The thread runtime is already vanilla and the MVP needs no new island.
T-002Client-only schema over new server routes. Existing message posting covers the feedback loop.
T-003Constrained .excalidraw save route over generic artifact writes. Narrow writes reduce path and content risk.

Assumptions

  • A-001 · Assistant artifacts fit inside stored message text. If wrong: add file-backed artifact loading.
  • A-002 · Composer-fill is acceptable for MVP. If wrong: add explicit per-action auto-send.

Reversibility

R-001 · medium. Remove the new runtime module, editor page, route save branch, CSS blocks, tests, and thread.js import/calls; no data migration exists.
