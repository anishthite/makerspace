UI layout

  1. Excalidraw source: keep interactive pan/zoom for real .excalidraw files.
  2. Rendered image: show existing .png, .svg, .jpg, .webp, and .gif diagram artifacts as lightweight image cards.
  3. Intent: require assistant messages plus diagram/render/inline/screenshot context so logos and random static assets do not become cards.
  4. Access: serve images through an authorized thread artifact route instead of assuming workspace paths are static URLs.

Decisions

IDChoice · Rationale
D-001Render image artifacts as first-class diagrams. Most previous successful diagram answers mention PNG/SVG outputs, not just Excalidraw sources.
D-002Serve images from the thread workspace through /api/threads/:name/artifacts/file. Workspace paths are not public URLs.
D-003Use positive context for image paths. This shows diagrams and screenshots while skipping logo/favicon/code-cleanup mentions.
D-004Add CSP sandbox headers on raw image artifacts. SVGs can be opened directly, so the response must stay inert.
