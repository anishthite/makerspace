cold local dispatch

nogit · worktree /Users/anishthite/workspace/makerspace · 2026-06-17 · status in-progress · blast medium

Summary

Goal
Make a normal empty-session POST /api/chat start Pi's first provider call under 1000 ms without claiming a warm or intent bridge.
Source
Local Pi SDK starts the agent; exe.dev VM provisions concurrently as the remote workspace for tool execution.
Metric
first_llm_call_start = Date.now() - submittedAtMs at the wrapped local SDK streamFn.
Cold guard
Verifier uses empty SESSION_DATA_PATH, WARM_BRIDGE_POOL_SIZE=0, and --require-cold-path.
Surface
src/server.js, src/local-pi-dispatch.js, src/config.js, scripts/measure-bootup.js, docs/tests.
Open Qs
0.

Algorithm

  1. Preload the Pi SDK module before the HTTP listener accepts chat traffic.
  2. On normal /api/chat, skip reusable bridge claims and create a localDispatchMode session.
  3. Start remote exe.dev provisioning in the background and expose a promise for remote tool operations.
  4. Create a local Pi SDK session with read, bash, edit, and write definitions backed by SSH into REMOTE_WORKSPACE_DIR.
  5. Wrap session.agent.streamFn and persist firstLlmLatencyMs at the first provider-call boundary.

Decisions

IDChoice · Rationale
D-001Move the first Pi provider call to the app server. Remote VM provisioning has measured 47–54 s cold latency.
D-002Proxy core tools over SSH instead of making a probe call. The measured call belongs to the user prompt's real Pi session.
D-003Skip reusable bridge claims when local dispatch is enabled. Empty-session verification must not depend on warm or intent bridges.

Tradeoffs

IDPicked over Rejected · Reason
T-001Local SDK agent over remote bridge agent. Provider-call latency becomes independent of VM boot latency.
T-002Remote tool proxy over local tools. Tool side effects stay in the exe.dev workspace.

Assumptions

  • A-001 · The server host has the pi CLI installed or PI_LOCAL_SDK_ENTRY set. If wrong: normal chat fails before launching remote fallback.

Reversibility

R-001 · medium. Set PI_LOCAL_DISPATCH=0 to return normal chat to bridge-backed VM execution.

Definition of done

  • Normal direct /api/chat uses localDispatchMode from an empty session store.
  • Verifier shows three cold runs with first_llm_call_start < 1000 ms.
  • Verifier output proves warmClaimed=false, warmBridge=false, and intentBridge=false.
  • npm test passes.
