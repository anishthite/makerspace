Decisions

IDChoice · Rationale
D-001Use the D1 REST API through fetch. Avoid a new SDK dependency for three SQL operations.
D-002Keep sessions as JSON blobs. Existing code already owns the session shape and needs no migration table spread.
D-003Use one KV table for settings, recents, Dockerfile, and profile text. These values are singleton documents.
D-004Create remote D1 database makerspace-state. Hosted deploys only need env wiring now.

Tradeoffs

IDPicked over Rejected · Reason
T-001D1 over Postgres. User requested D1 for now.
T-002Lazy schema creation over migrations. Two idempotent tables do not need a migration framework.

Reversibility

R-001 · medium. Unset MAKERSPACE_STATE_STORE to return to JSON files without deleting D1 data.
