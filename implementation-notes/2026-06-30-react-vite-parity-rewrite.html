main · makerspace · 2026-06-30 · shipped · blast high

Summary

Goal
Ship a React/Vite frontend with exact current routes, UI, and browser behavior.
Source
User requested full feature and UI parity.
Surface
public/, frontend/, build/deploy/desktop packaging, server static directory.
Schema
No API, session, or storage schema changes.
Routes
Keep direct .html URLs and copied design/reference pages.
Risk
thread.js SSE/trace/diff/artifact behavior is the main parity risk.
Open Qs
0.

Algorithm

  1. Generate a route manifest from current public/**/*.html.
  2. Build React/Vite as an MPA that emits current top-level filenames.
  3. Render current page markup through React first; load current browser modules after mount for zero behavior drift.
  4. Port imperative modules to React state route-by-route only after parity fixtures exist.
  5. Gate cutover on route crawl, screenshots, interaction tests, and existing unit tests.

UI layout

  1. / keeps project selector markup, auth pills, repo picker, folder picker, and recent projects.
  2. /workspace.html keeps launch composer, model/thinking controls, attachment row, and agent lanes.
  3. /thread.html keeps header, agent rail, trace, diff box, timeline, notes shell, and composer.
  4. /settings.html, /history.html, /performance.html, and /desktop.html keep current DOM contracts.
  5. Design/reference pages stay copied until explicitly retired.

Decisions

IDChoiceRationale
D-001Use Vite MPA output over SPA-only routing.Direct .html links are public contracts.
D-002Render existing markup through React before porting behavior.Exact parity beats a big-bang rewrite.
D-003Keep public/styles.css as the source style layer during migration.CSS drift is the easiest visual regression.
D-004Serve dist/ when built and public/ otherwise.Local dev remains usable before a build.

Tradeoffs

IDPicked over rejectedReason
T-001Compatibility bridge over immediate hook rewrite.The current thread state machine needs fixtures before refactor.
T-002Generated route manifest over hand-maintained list.The repo has many reference pages that are easy to drop.

Assumptions

  • A-002 · Old design/reference pages remain product surface unless explicitly retired.
