## Rubric

| Criterion | Weight | Definition |
|---|---:|---|
| Single sharp wedge (`wedge`) | 20 | Does the page lead with one memorable, specific wedge instead of a feature inventory? Full credit if the headline can own a category in one sentence. |
| Local Pi uniqueness (`local_pi_unique`) | 20 | Does it foreground the strongest defensible point: your local Pi setup, skills, prompts, providers, and AGENTS.md habits running on a remote agent? |
| Browser + remote agent clarity (`remote_browser`) | 15 | Does it make clear that Pi runs from the browser on real remote sandboxes, not just a dashboard, report viewer, or artifact host? |
| Recurring cloud loops (`recurring_loops`) | 15 | Does it make recurring/standing agents and better cloud iteration loops feel easy, useful, and tied to coding work? |
| Setup/env customization (`custom_env`) | 10 | Does it explain how the agent learns repo rules, setup commands, secrets, package managers, checks, and model/provider defaults without sounding like plumbing? |
| Evidence tied to work (`work_evidence`) | 10 | Does it show evidence as proof of agent work: diffs, logs, checks, screenshots, decisions, failures, and next actions, not generic HTML artifacts? |
| Buyer urgency (`urgency`) | 10 | Does it create an immediate reason to try it now with a clear pain, job, and payoff? Penalize abstract infrastructure language. |

## Final landing

- **Headline:** Run your Pi setup in a browser sandbox.
- **Subhead:** Spanner opens a real remote coding sandbox, loads your AGENTS.md, skills, prompts, providers, setup commands, and checks, then returns the work as diffs, logs, screenshots, and a repeatable run you can reopen tomorrow.
- **Primary CTA:** Open a Pi sandbox
- **Secondary CTA:** See the setup receipt
- **Hero visual:** A single browser-window mockup. Left rail: 'Setup receipt' with checked rows for AGENTS.md, repo rules, package manager, secrets, model/provider defaults, and checks. Main pane: live remote sandbox status with a terminal snippet, one diff preview, one passing check, and a small screenshot thumbnail. Bottom-right card: 'Tomorrow's pass: same Pi setup, fresh sandbox, new evidence.'
- **Strip:** Your Pi habits. Fresh remote sandboxes. Reviewable work. Repeat tomorrow.

### Cards

- **Starts with your Pi** — Every run begins by loading the setup you already trust: repo instructions, skills, prompts, providers, setup commands, secrets, and checks.
- **Runs in a real browser sandbox** — Start, watch, and reopen Pi work from any browser while the coding agent runs on a remote machine built for the repo.
- **Comes back with evidence** — Standing runs return diffs, logs, checks, screenshots, decisions, failures, and next actions—not vague agent summaries.

### Path

1. H1 names the category: Pi setup inside a browser sandbox.
2. Subhead proves this is local Pi inheritance on a real remote agent.
3. Primary CTA starts the sandbox; secondary CTA anchors skepticism in the receipt.
4. Hero visual shows receipt before work, then diff/check/log evidence from the remote run.
5. Strip compresses the promise into four beats: habits, sandbox, evidence, repeat.
6. Three cards explain setup inheritance, browser operation, and recurring proof without adding new wedges.
7. Footer adds urgency: close the laptop, run another repo pass, come back tomorrow.

### Why it wins

It keeps the strongest defensible wedge intact: the user's local Pi setup running inside a remote browser-accessible sandbox. The receipt-before-diff visual makes customization and trust obvious without sounding like plumbing, while the tomorrow card covers recurring loops without turning the page into a scheduler pitch. It is specific enough to own, simple enough to implement as frontend/desktop.html, and concrete enough for a Pi user to know why to try it now.

### Risks

- The H1 is clear but calmer than pain-led alternatives like laptop sleep; ads or secondary copy may need sharper urgency.
- The hero visual can become crowded if every setup and evidence item is rendered at equal weight; keep it to one receipt, one diff, one check, one tomorrow card.
- New visitors who do not already know Pi may need a small contextual line or tooltip, but do not dilute the hero for them.
- Recurring runs are intentionally secondary; if recurring becomes the main product motion, the tomorrow card may need to become a full section.
